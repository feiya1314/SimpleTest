# 大模型训练全流程

从零开始训练一个大模型，按步骤拆解每一步做什么、难点在哪。

---

## 第一步：确定目标

**做什么**：决定参数规模、架构、数据量、算力预算

| 决策项 | 说明 | 难度 |
|:------|:-----|:----:|
| **参数量** | 7B / 13B / 70B / 180B？ | 🟡 需要根据算力预算决定 |
| **架构** | 解码器（GPT式）？MoE（DeepSeek式）？ | 🟡 影响训练和推理方式 |
| **数据量** | Scaling Law：更多参数需更多数据（约20倍参数量的token数） | 🟢 经验法则 |
| **算力预算** | 多少钱、多少卡、跑多久 | 🔴 算力决定一切 |

**难点**：
- **Scaling Law 权衡**——同样算力，选 70B 少训点数据，还是 7B 多训数据？不同选择结果完全不同
- **卡数选择**——卡太少训得慢，卡太多通信带宽成瓶颈

---

## 第二步：准备数据

**做什么**：收集、清洗、处理训练数据。这是最耗时的一步。

### 处理流程

```
原始互联网数据（PB级）
    │ 爬取
    ▼
原始文本
    │ 清洗过滤
    ▼
高质量文本  ← 这一步砍掉 ~60-80% 的数据
    │ 去重（MinHash / Exact Dedup）
    │ 安全过滤（PII / Toxic）
    │ 质量评分（Perplexity 打分）
    ▼
精炼数据集
    │ Tokenization（BPE分词）
    ▼
Token ID 序列  ← 最终喂给模型的数据
```

### 数据配比

| 数据来源 | 占比 | 作用 |
|:--------|:----:|:-----|
| 网页（Common Crawl） | ~50% | 语言多样性和知识广度 |
| 书籍/论文 | ~30% | 长文本、深度知识、推理能力 |
| 代码 | ~15% | 逻辑推理和编程能力 |
| 数学/科学 | ~5% | 精确推理和科学知识 |

**难点**：
- 🔴 **最难的一步**——数据质量比数量更重要。Common Crawl 里 80% 是垃圾网页，怎么去垃圾留知识，非常考验工程能力
- **去重**：不做去重，模型会"背下"重复内容而非"学到"知识
- **混合比例**：代码太少→推理弱；代码太多→语言自然度下降。比例靠实验摸索

---

## 第三步：选择训练基础设施

**做什么**：搭建 GPU 集群，配置分布式训练框架

### 硬件配置（72B 模型为例）

| 规模 | 配置 | 时间 |
|:----|:------|:----:|
| 小规模 | 8×H100(80G) | 一年多（不现实） |
| 中规模 | 64×H100 | 约 2-3 个月 |
| 大规模 | 512×H100 | 约 10-15 天 |

### 分布式策略

```
单张 H100 80GB 只能跑 ~7B（FP16）模型
72B 模型必须拆分到多张卡上

三种拆法：

① 数据并行（DP）：
   每张卡放完整模型，分不同的数据
   同时训练，梯度同步
   → 适合小模型（<7B）

② 张量并行（TP）：
   把一层矩阵切成两块，放两张卡上
   卡1算一半维度，卡2算另一半，结果合并
   → 适合大模型（>13B），但卡间通信量大

③ 流水线并行（PP）：
   卡1：1-20层；卡2：21-40层；卡3：41-60层
   数据按流水线在各卡间传递
   → 通信量小，但 GPU 利用率可能不高

实际训练：三者同时用（3D Parallelism）
例如 64 卡：TP=8 × PP=4 × DP=2
```

**难点**：
- 🔴 **通信瓶颈**——TP 每层算一次就要同步一次，跨机器通信速度不够就拖慢整个集群（InfiniBand 为此存在）
- **稳定训练**——64 卡连续跑一个月，中间任何一张卡故障都会中断训练。实际训练中几乎每天遇到硬件故障

---

## 第四步：前向传播

**做什么**：把数据喂给模型，计算预测值和真实值的差距（Loss）

```
输入 token 序列：[312, 879, 4521, 3301, 42, ...]
标签（右移一位）：[879, 4521, 3301, 42, 990, ...]

每个位置：
  输入特征 → Transformer 80层 → 概率分布 → 真实 token
                                    ↓
                         Loss = -log(P(真实token))

Loss = 预测与真实之间的差距
```

**难点**：
- 🟡 前向传播本身不难，难点在**性能优化**——怎么让矩阵乘法跑最快（FlashAttention、算子融合）

---

## 第五步：反向传播

**做什么**：从最后一层开始，逐层计算每个参数对 Loss 的"责任"（梯度）

```
Loss → ∂Loss/∂W_output → ∂Loss/∂W_N → ... → ∂Loss/∂W_1
                                        ↑
                                   链式法则逐层传递
```

**难点**：
- 🔴 **显存爆炸**——反向传播需保存每层的中间激活值（activation）。72B 模型所有中间值可能超过 2TB。需要用激活值检查点（activation checkpointing）：保存一部分、丢弃一部分、需要时重新计算

---

## 第六步：参数更新

**做什么**：用梯度更新参数，让 Loss 下降

```python
# 实际用的 AdamW 优化器：
m_t = β₁·m_{t-1} + (1-β₁)·g_t           # 动量（梯度平滑）
v_t = β₂·v_{t-1} + (1-β₂)·g_t²          # 自适应学习率
w_t = w_{t-1} - lr · m_t / (√v_t + ε)   # 更新参数
```

**难点**：
- 🟡 **学习率调度需要经验**——预热多少步、最大学习率多少、余弦衰减周期多长。设错了模型不收敛或收敛慢
- **混合精度训练**——大部分用半精度（快）但梯度用全精度（准）。精度转换处理不好会导致训练不稳定

---

## 第七步：模型评估与检查

**做什么**：定期评估模型是否在学、是否过拟合

```
每个 N 步（如 N=1000）：
  ① 检查训练 Loss → 还在下降？
  ② 检查验证 Loss → 也下降？（验证 Loss 上升=过拟合）
  ③ 跑下游 Benchmark：
     - MMLU（知识）
     - HumanEval（编程）
     - GSM8K（数学推理）
```

**难点**：
- 🟡 **数据泄露**——测试数据混入训练集，评估结果不可信。需确保训练/评估数据不重叠
- **loss 下不去怎么办**——数据问题？学习率问题？还是模型容量到极限了？难定位

---

## 第八步：继续预训练（可选）

**做什么**：通用预训练后，用领域数据继续训练

```
通用预训练：Common Crawl + Wikipedia + Books（~70B token）
    ↓
领域继续预训练：法律/医学/代码（~5-10B token）
    ↓
领域专门模型
```

**难点**：
- 🔴 **灾难性遗忘**——学了新数据后遗忘旧知识。需小心控制学习率和新旧数据比例

---

## 第九步：指令微调（SFT）

**做什么**：用高质量"指令-回答"对训练模型学会遵循指令

```json
{
  "instruction": "法国的首都是什么？",
  "output": "法国的首都是巴黎。"
}
```

**关键**：数据质量 >>> 数据数量。1000 条高质量指令 > 10 万条低质量数据

**难点**：
- 🔴 **数据质量是天花板**——SFT 数据决定模型上限。OpenAI 花数千人工标注员做这件事，成本极高
- **多样性覆盖**——所有能力维度（问答、写作、翻译、代码、推理）都要覆盖到

---

## 第十步：偏好对齐（RLHF / DPO）

**做什么**：让模型回答更符合人类偏好——更有帮助、更诚实、更无害

### DPO（简单做法）

```python
# Step 1：收集偏好数据
# 对同一 prompt 生成多个回答，让人工排序：A > B > C

# Step 2：直接训练
loss = -log σ(β × (P(A|prompt) - P(B|prompt)))
#           偏好回答概率↑         不喜欢回答概率↓
```

### RLHF（更复杂做法）

```python
# Step 1：训练奖励模型（给回答打分）
# Step 2：用 PPO 强化学习更新主模型
#   生成回答 → 奖励模型打分 → 调参数让得分更高
#   同时加 KL 散度惩罚 → 不让模型偏离 SFT 太远
```

**难点**：
- 🔴 **PPO 极其难调**——RL 训练比监督训练不稳定得多，多个超参数都极其敏感
- **reward hacking**——奖励模型不完美，主模型总能找到"骗"过它的方法
- **标注标准不一致**——不同标注员对"好的回答"定义不同

---

## 第十一步：部署与推理优化

**做什么**：把训练好的 FP16 模型压缩、加速、上线

```
FP16 模型（~144GB for 72B）
    │ 量化
    ▼
INT4 模型（~36GB for 72B）← 单张 H100 能跑
    │ KV Cache 优化 / 连续批处理 / 算子融合
    ▼
可用的 API 服务
```

**难点**：
- 🟡 量化质量损失的控制、推理延迟和吞吐量的权衡

|:----|:----:|:--------:|
| 确定目标 | 1-2 周 | 🟡 |

| **总计** | **~2-3 个月** | |

## 大模型训练最难的三个问题

| 排名 | 问题 | 为什么难 |
|:---:|:-----|:---------|
| 🥇 | **数据质量** | 互联网数据 80% 垃圾。怎么选、怎么洗、怎么配比，决定模型天花板。无银弹，靠经验+实验 |
| 🥈 | **训练不稳定** | 上万张 H100 连续跑几个月，一次梯度溢出、节点掉线、通信超时都可能导致中断。恢复成本极高 |
| 🥉 | **对齐难度** | RLHF/DPO 训练信号是"人类偏好"，本身模糊且不一致。PPO 超参数调节非常玄学 |

---

## 一句话总结

> **大模型训练 = 海量数据（数据准备最难） + 海量算力（训练稳定最难） + 人类反馈（对齐最玄学）。** 三者缺一不可——数据垃圾→模型垃圾；训练不稳→训不出来；对齐做不好→模型不好用。💰🔥
