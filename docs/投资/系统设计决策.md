# 新闻驱动 A 股分析系统 — 设计决策树

> 基于 20 轮问答形成的完整设计决策记录

---

## 一、核心定位

| 决策项 | 结论 |
|--------|------|
| 产品定位 | 个人决策辅助工具（第一阶段）→ 后续开放为公开平台 |
| 目标 | 关注每天每小时国内热点新闻，分析新闻与股票的关联及利好/利空 |

---

## 二、数据层

### 2.1 新闻来源
- **爬虫（B）**：财联社电报、新浪财经、雪球
- **RSS 订阅（D）**：补充财经媒体源
- **阶段演进**：初期聚焦财经垂直媒体 + 社媒 → 后续加入政策发布源（国务院/发改委/央行）

### 2.2 推送频率
- **实时推送（C）**：财联社电报到达后逐条触发分析
- 若 API 成本敏感，退化为定时批量（早 8:30 / 午 12:00 / 收市 15:30）

### 2.3 新闻优先级排序
- **基于热度的漏斗（D）**：
  - 财联社电报：全部进入分析
  - 社媒内容（雪球/微博）：按转发/阅读量排序，Top N 条进入 LLM
  - 可根据关注股票/概念做二次筛选

## 三、分析层

### 3.1 新闻→股票关联方式
- **关键词粗筛 + LLM 深度分析（C）**
  - 关键词匹配：快速过滤，标注候选概念/股票
  - LLM 深度分析：对过滤后的新闻做相关度评分、情感判断、影响评估

### 3.2 LLM 选型
- **DeepSeek API 优先（A）→ 本地模型后续替换（D）**
  - 初期用 DeepSeek API 快速验证管道可行性
  - 数据验证跑通后，考虑本地模型替换高吞吐环节

### 3.3 LLM 输出结构（每条新闻）

```json
{
  "related_stocks": ["中信海直", "亿航智能"],
  "related_concepts": ["低空经济", "无人机"],
  "sentiment": "positive",
  "confidence": 0.9,
  "impact_level": "major",
  "time_horizon": "中长期",
  "impact_dimensions": ["政策面"],
  "reason": "政策落地，明确实施日期，利好低空经济板块龙头"
}
```

字段说明：

| 字段 | 取值 | 说明 |
|------|------|------|
| `sentiment` | positive / negative / neutral | 情感极性 |
| `confidence` | 0.0 ~ 1.0 | 置信度 |
| `impact_level` | major / moderate / minor | 影响程度 |
| `time_horizon` | 短期 / 中期 / 长期 | 影响时间范围 |
| `impact_dimensions` | 政策面 / 基本面 / 资金面 / 情绪面 | 影响维度 |

### 3.4 概念评分机制

- **混合模式（C）**：
  - 基础评分（政策支持力度、产业空间、龙头强度等 10 项）：手动定期更新（每周复盘）
  - 动态评分（资金关注度、情绪面）：由新闻分析结果自动更新

### 3.5 评分更新规则

- **加权累计 + 时间衰减（B）**：
  - 重大利好 / 重大利空：±2 分
  - 利好 / 利空：±1 分
  - 时间衰减系数：当天 1.0，昨天 0.8，前天 0.5，依次递减
  - 每日最终得分 = 所有有效事件的加权之和
  - 人工可在每周复盘中修正或覆盖

### 3.6 概念相位判断

- **量化规则自动判断 + 人工确认（D）**：
  - 系统根据新闻量趋势、情绪分趋势等量化指标自动标注阶段（萌芽/发酵/主升/高潮/退潮/分化）
  - 每周复盘时人工确认或修正
  - 判断条件参考现有框架：主升期 = 正面新闻持续 + 扩散至中后排股票 + 龙头走强

### 3.7 行情数据

- **有，第二阶段接入（D）**：
  - 概念评分触发阈值 + 技术面确认（放量突破 + 龙头涨停）才标记为"高置信度信号"
  - 初期纯新闻驱动，后续叠加行情数据

### 3.8 行情数据接入分析（补充说明）

#### 3.8.1 股价数据能解决什么

| 当前短板 | 股价数据如何补强 |
|---------|----------------|
| 新闻利好/利空判断是静态的，无法区分市场是否已定价 | 结合股价位置判断：低位利好 = 真利好，高位利好 = 可能出货 |
| 概念评分靠手动更新，滞后且主观 | 自动计算板块涨跌幅、资金净流入/流出、板块内个股涨跌分布 |
| 无法区分"真突破"和"假突破" | 成交量 + 价格形态双重确认，放量突破 vs 缩量假突破 |
| 没有回测能力，难以验证信号有效性 | 用历史行情 + 历史新闻做信号回测，计算胜率/盈亏比 |

#### 3.8.2 建议接入的数据维度

| 优先级 | 数据维度 | 数据源 | 用途 |
|--------|---------|--------|------|
| P0 | 概念板块指数（日/周 OHLCV） | 东方财富/同花顺概念板块 | 判断概念整体趋势、涨跌幅、成交量变化 |
| P0 | 个股日线量价数据（OHLCV + 成交额） | akshare / tushare / 聚宽 | 确认个股信号、计算均线位置、量价关系 |
| P1 | 北向资金流向（沪深股通） | akshare / 东方财富 | 判断外资对概念/个股的态度 |
| P1 | 主力资金流向（大单净流入/流出） | 东方财富 Choice | 识别主力资金动向，配合新闻验证 |
| P2 | 龙虎榜数据 | 东方财富 | 识别机构 vs 游资 vs 散户行为 |
| P2 | 融资融券余额 | 交易所公开数据 | 判断杠杆资金热度，辅助顶部/底部判断 |

#### 3.8.3 架构演进建议

```
Phase 1（当前方案）:
  新闻 → LLM分析 → 概念评分 → 看板展示

Phase 1.5（推荐中间态 — 加入行情确认）:
  新闻 → LLM分析 → 概念评分 → 叠加行情确认 → 看板展示 + 信号推送
                                  ↑
                          行情数据接口 (akshare 免费接口)
```

关键原则：不需要等到 Phase 3 才接入行情。Phase 1 完成后即可通过 **akshare**（免费，无需 token）接入基础行情数据。

#### 3.8.4 新增分析维度（信号增强规则）

每条新闻分析后，对关联的每只股票/概念增加以下判断：

| 判断维度 | 规则 | 影响 |
|---------|------|------|
| 价格位置 | 当前价相对 MA20/MA60 的位置 | MA20 上方 = 上升趋势，加分；MA20 下方 = 下降趋势，减分 |
| 量价配合 | 当日成交量 vs 20日均量 | 放量 = 有资金认可，加分；缩量 = 市场不关注，减分 |
| 板块相对强度 | 概念指数涨跌幅 vs 大盘 | 跑赢大盘 = 资金聚焦，加分 |
| 信号置信度综合 | 以上条件 + 新闻情感分 | 三者皆正面 → 高置信度信号；任一负面 → 降低置信度或过滤 |

只有**新闻正面 + 股价在 MA20 上方 + 放量**三者同时满足，才标记为"高置信度信号"推送给用户。

## 四、技术层

### 4.1 技术栈

| 组件 | 选型 |
|------|------|
| 整体架构 | Python 全栈 |
| 数据采集 | Python（requests + BeautifulSoup / Scrapy） |
| 数据库 | PostgreSQL |
| 搜索增强（后续） | Elasticsearch（现有项目已集成） |
| Web 看板 | Flask + 简单 HTML 模板 |
| 消息推送 | 微信 / 飞书（后续增强） |

### 4.2 分析管道流程

```
新闻源 → 采集器 → 热度漏斗排序 → LLM 分析 → 入 PostgreSQL → 概念评分更新 → Web 看板 + 推送
```

### 4.3 知识库：概念↔股票映射

- **AI 自动抓取 + 人工校验（D）**：
  - 种子数据：已有 `docs/a_stock_concept_replay/` 中的概念复盘成果
  - 自动同步：爬取东方财富/同花顺的概念板块成分股
  - 人工审核：关键概念由你审核修正

## 五、展现层

### 5.1 Web 看板布局

- **混合布局（D）**：
  - **左侧**：概念热度排行（按当日新闻量 / 情绪分排序）
  - **右侧**：今日关键新闻流（每条附关联概念/股票/情感标签）
  - **底部**：关注股票快照（累计情绪得分 + 今日相关新闻数）

### 5.2 推送通知

- 重要概念评分突变、高置信度信号出现时推送到微信/飞书
- 架构上预留推送接口，初期先做 Web 看板

## 六、验证与迭代

- **阶段一：周度复盘（B）**
  - 每周回看系统输出的高置信度信号
  - 对照实际走势打分（命中 / 不命中 / 部分命中）
  - 统计胜率，识别系统短板

- **阶段二：量化回测**
  - 积累 2-3 个月数据后
  - 用历史新闻和历史行情做完整回测
  - 计算胜率 / 盈亏比 / 夏普比率

---

## 七、阶段规划

### Phase 1：最小闭环
- Python 采集财联社电报
- DeepSeek API 做新闻分析
- 存入 PostgreSQL
- Flask 简单看板展示

### Phase 2：功能增强
- 加入社媒源（雪球等）
- 热度漏斗排序
- 概念评分自动更新
- 微信/飞书推送

### Phase 3：深度集成
- 本地模型部署
- 行情数据接入 + 信号确认
- 量化回测系统
- 考虑逐步开放给更多用户
