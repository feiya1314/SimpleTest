# 1. 值传递和引用传递

Java是值传递还是引用传递？

**答案：Java只有值传递。**

```java
public static void main(String[] args) {
    int x = 1;
    change(x);
    System.out.println(x);  // 1，值未变

    User u = new User("张三");
    changeUser(u);
    System.out.println(u.getName()); // 李四，对象内容变了
}

static void change(int x) { x = 2; }
static void changeUser(User u) { u.setName("李四"); }
```

**理解：**

- 基本类型：传递的是值的**副本**，方法内修改不影响原变量
- 引用类型：传递的是**引用地址的副本**，两个引用指向同一个对象，通过引用修改对象内容会影响原对象
- 但如果方法内让引用指向新对象（`u = new User()`），原引用不受影响

**面试考点：**
- "引用传递"是指传递引用本身，方法内可以改变引用指向
- Java传递的是引用的拷贝，所以是值传递

# 2. 包装类缓存池与自动装箱

Integer缓存池的原理是什么？自动装箱拆箱有哪些陷阱？

**原理分析**

**包装类缓存池：**

| 包装类 | 缓存范围 |
|-------|---------|
| Boolean | true / false |
| Byte | -128~127 |
| Short | -128~127 |
| Integer | -128~127（可通过`-XX:AutoBoxCacheMax`调整） |
| Long | -128~127 |
| Character | 0~127 |

```java
Integer a = 127;   // 等价于 Integer.valueOf(127)，走缓存
Integer b = 127;
System.out.println(a == b);  // true，同一个缓存对象

Integer c = 128;
Integer d = 128;
System.out.println(c == d);  // false，new了新对象
```

**自动装箱拆箱：**

编译器的语法糖：
- `Integer x = 100` → 编译为 `Integer.valueOf(100)`（装箱）
- `int y = x` → 编译为 `x.intValue()`（拆箱）

**常见陷阱：**

1. **== vs equals**：==比较对象引用，equals比较内容。包装类用==时注意缓存范围
2. **NPE风险**：包装类参与运算时自动拆箱，如果为null则抛NPE
3. **循环内装箱**：`Long sum = 0L; for(...) sum += i;` 每次sum+=i都会装箱拆箱，产生大量对象，应使用long基本类型

> ==和equals的区别？

- **==**：基本类型比较值，引用类型比较内存地址
- **equals**：Object默认比较地址，但String、Integer等重写为比较内容

# 3. final关键字

final修饰类、方法、变量分别有什么作用？

**修饰类：** 类不能被继承（如String、Integer等不可变类）

**修饰方法：** 方法不能被重写，但可以重载。private方法隐式是final的

**修饰变量：**

- **基本类型**：值不可变
- **引用类型**：引用指向不可变，但对象内容可变（`final User u`不能指向新对象，但可以改u.setName）
- **参数**：方法内不能重新赋值

**final域重排序规则：** JMM保证final域的初始化完成在构造器返回之前（防止构造函数溢出时看到未初始化的final值）

```java
public class FinalExample {
    private final int x;  // final保证构造完成即可见
    private int y;

    public FinalExample() {
        x = 1;  // final写
        y = 2;  // 普通写
    }
}
```

# 4. static关键字

static修饰符的作用和注意事项？

**修饰变量：** 类变量，所有实例共享一份，类加载时初始化

**修饰方法：** 类方法，不能访问实例变量和方法（没有this引用）

**修饰代码块：** 静态代码块，类加载时执行一次，用于初始化静态资源

**修饰内部类：** 静态内部类，不持有外部类的引用，可以独立创建

```java
public class Outer {
    private static String staticField = "类变量";
    private String instanceField = "实例变量";

    static { System.out.println("类加载时执行一次"); }

    static void staticMethod() {
        System.out.println(staticField);  // ✅
        System.out.println(instanceField); // ❌ 编译错误
    }

    static class StaticInner {
        // 不持有Outer引用
    }
}
```

**父子类static方法：** static方法不能被重写（override），只能被隐藏（hide）。子类定义同名static方法不会覆盖父类方法，调用时取决于引用类型而非实际对象。

# 5. 异常体系

Java异常体系的结构是什么？如何正确处理异常？

**结构：**

```
Throwable
├── Error（不可处理）
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── NoClassDefFoundError
└── Exception（可处理）
    ├── RuntimeException（非受检/unchecked）
    │   ├── NullPointerException
    │   ├── IllegalArgumentException
    │   ├── IndexOutOfBoundsException
    │   └── ArithmeticException
    └── 其他（受检/checked）
        ├── IOException
        ├── SQLException
        └── ClassNotFoundException
```

**受检 vs 非受检：**

| 维度 | 受检异常（Checked） | 非受检异常（Unchecked） |
|------|-------------------|---------------------|
| 继承 | 非RuntimeException | RuntimeException及其子类 |
| 处理 | 必须try-catch或throws | 可选处理 |
| 触发 | 外部环境问题（文件不存在、网络断开） | 程序逻辑错误（空指针、数组越界） |

**异常处理最佳实践：**

1. **不要捕获泛泛的Exception**：捕获具体的异常类型
2. **不要忽略异常**：空的catch块是罪恶，至少要打印日志
3. **不要用异常控制流程**：异常性能差（需要构建栈轨迹）
4. **尽早抛出、延迟捕获**：能处理的地方处理，不能处理就抛出
5. **try-with-resources**：自动关闭资源，避免finally中手动close

```java
// ✅ 正确做法
try (InputStream is = new FileInputStream("file.txt")) {
    // 使用资源
} catch (FileNotFoundException e) {
    log.error("文件不存在", e);
    throw new BusinessException("文件不存在");
}

// ❌ 错误做法
try {
    // ...
} catch (Exception e) {
    // 空的catch块或只是e.printStackTrace()
}
```

**自定义异常：** 继承RuntimeException（非受检）或Exception（受检），包含错误码和上下文信息，便于定位问题。

# 6. 泛型

Java泛型的实现原理？什么是类型擦除和桥方法？

**原理：** Java泛型通过**类型擦除**实现。编译时进行类型检查和推断，编译后泛型信息被擦除，替换为上限类型（无上限则为Object）。

```java
// 编译前
List<String> list = new ArrayList<>();
list.add("hello");
String s = list.get(0);

// 编译后（类型擦除）
List list = new ArrayList();
list.add("hello");
String s = (String) list.get(0);  // 自动插入类型转换
```

**桥方法（Bridge Method）：** 编译器在泛型继承时自动生成的合成方法，用于保持多态。子类重写父类泛型方法后，擦除导致签名不匹配，桥方法充当桥梁。

```java
class Node<T> {
    T data;
    public void setData(T data) { this.data = data; }
}
class MyNode extends Node<Integer> {
    public void setData(Integer data) { ... }
    // 编译器生成桥方法（字节码中可见）：
    // public void setData(Object data) { setData((Integer) data); }
}
```

**类型擦除带来的限制：**

1. **不能实例化泛型类型**：`new T()` 编译错误
2. **不能创建泛型数组**：`new T[10]` 编译错误
3. **不能使用instanceof**：`list instanceof List<String>` 编译错误
4. **静态变量类型不能是类型参数**：`static T field;` 编译错误
5. **重载冲突**：`void method(List<String>)` 和 `void method(List<Integer>)` 擦除后相同签名

**通配符：**

| 通配符 | 含义 | 可读 | 可写 |
|--------|------|------|------|
| `? extends T` | 上界通配符（生产） | ✅可以读为T | ❌不能写（不知道具体类型） |
| `? super T` | 下界通配符（消费） | ❌只能读为Object | ✅可以写T |
| `?` | 无限定通配符 | ✅只能读为Object | ❌不能写 |

**PECS原则：** Producer Extends, Consumer Super

```java
// 生产者：只读，用 extends
void readAll(List<? extends Number> list) {
    Number n = list.get(0);  // ✅
    list.add(1);             // ❌
}

// 消费者：只写，用 super
void writeAll(List<? super Integer> list) {
    list.add(1);             // ✅
    Object o = list.get(0);  // 只能读为Object
}
```

# 7. 反射

反射的原理是什么？主要API有哪些？在Spring中如何应用？

**原理：** JVM在类加载时将.class文件解析为 `java.lang.Class` 对象，反射通过这个Class对象获取类的元数据（方法、字段、构造器等）。

**获取Class对象的三种方式：**

```java
Class<?> clazz = Class.forName("com.example.User");
Class<?> clazz = User.class;
Class<?> clazz = user.getClass();
```

**主要API：**

```java
// 获取构造器并实例化
Constructor<?> constructor = clazz.getDeclaredConstructor(String.class);
User user = (User) constructor.newInstance("张三");

// 获取方法并调用
Method method = clazz.getDeclaredMethod("getName");
String name = (String) method.invoke(user);

// 获取字段并修改
Field field = clazz.getDeclaredField("name");
field.setAccessible(true);    // 访问private字段
field.set(user, "新名字");

// 获取注解
Annotation[] annotations = clazz.getAnnotations();
```

**setAccessible：** 抑制Java语言访问权限检查，使反射可以访问private成员。频繁调用有性能开销，应缓存反射对象。

**性能开销：**
- 反射比直接调用慢（跳过JVM内联优化、类型检查、安全检查等）
- 慢约 **1~2个数量级**
- 优化方式：缓存Method/Field对象、尽量用接口调用、使用setAccessible(true)减少安全检查

**Spring中的应用：**
- IOC容器：通过反射读取类的构造器、字段信息，实现**依赖注入**
- @Autowired：通过反射字段上的注解，**注入依赖对象**
- AOP：结合动态代理，对目标类创建代理对象
- 配置解析：读取@Component、@Service等注解，扫描包**注册Bean**
- SpEL表达式：反射调用方法访问对象属性

# 8. 动态代理

JDK动态代理和CGLIB的区别？动态代理的使用场景？

**JDK动态代理：**
基于接口，通过 `java.lang.reflect.Proxy` 和 `InvocationHandler` 在运行时动态生成代理类。

```java
// InvocationHandler - 调用处理器
public class LogHandler implements InvocationHandler {
    private final Object target;

    public LogHandler(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("before");
        Object result = method.invoke(target, args);
        System.out.println("after");
        return result;
    }
}

// 创建代理对象
UserService proxy = (UserService) Proxy.newProxyInstance(
    target.getClass().getClassLoader(),
    target.getClass().getInterfaces(),
    new LogHandler(target)
);
proxy.doSomething();
```

**CGLIB动态代理：**
基于继承，通过ASM字节码技术生成目标类的子类，覆盖非final方法。

```java
// MethodInterceptor
public class LogInterceptor implements MethodInterceptor {
    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        System.out.println("before");
        Object result = proxy.invokeSuper(obj, args);
        System.out.println("after");
        return result;
    }
}

// 创建代理
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(UserService.class);
enhancer.setCallback(new LogInterceptor());
UserService proxy = (UserService) enhancer.create();
```

**JDK vs CGLIB对比：**

| 维度 | JDK动态代理 | CGLIB |
|------|------------|-------|
| 原理 | 基于接口，生成实现类 | 基于继承，生成子类 |
| 要求 | 目标类必须实现接口 | 目标类不能是final |
| 目标方法 | 接口中声明的方法 | 非final方法（final/static不行） |
| 依赖 | JDK原生，无需额外包 | 需要引入cglib/ASM |
| 性能 | 创建快，调用稍慢 | 创建慢，调用快（MethodProxy优化） |

**Spring AOP的选择策略：**
- 目标类实现了接口 → 默认用**JDK动态代理**
- 目标类未实现接口 → 用**CGLIB**
- Spring Boot 2.x+ 默认用CGLIB（proxy-target-class=true）

**使用场景：**
- AOP面向切面编程（事务、日志、权限控制）
- RPC框架远程调用（对本地接口生成远程调用代理）
- 延迟加载（MyBatis懒加载代理）
- 方法拦截器

# 9. 注解

注解的保留策略和元注解有哪些？APT是什么？

**元注解：**

| 元注解 | 说明 |
|--------|------|
| @Retention | 保留策略 |
| @Target | 可修饰的目标（方法、字段、类等） |
| @Inherited | 是否可继承，父类注解可被子类继承 |
| @Documented | 是否包含在Javadoc中 |
| @Repeatable | 是否可重复标注 |

**RetentionPolicy（保留策略）：**

| 策略 | 级别 | 说明 |
|------|------|------|
| SOURCE | 源码 | 编译后丢弃，如 @Override |
| CLASS | 字节码 | 编译到class，运行时不可见（默认） |
| RUNTIME | 运行时 | 可通过反射读取，如 @Autowired |

**自定义注解：**

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Log {
    String value() default "";
    Level level() default Level.INFO;
}
```

**运行时注解 vs 编译时注解：**

| 类型 | 保留策略 | 获取方式 | 典型应用 |
|------|---------|---------|---------|
| 运行时注解 | RUNTIME | 反射读取 | Spring @Autowired |
| 编译时注解 | SOURCE/CLASS | APT处理 | Lombok @Data |

**APT（Annotation Processing Tool）：**
编译时注解处理器，在编译期扫描和处理注解，自动生成代码。

- `@Override`：SOURCE级别，编译期语法检查
- **Lombok**：编译时通过APT生成getter/setter/构造器等，class文件中已有完整代码
- **AbstractProcessor**：自定义APT处理器，继承该类实现process()方法，生成Java源文件或代码

# 10. 枚举

枚举的本质是什么？枚举有哪些高级用法？

**本质：** 枚举类继承 `java.lang.Enum`，是final类。每个枚举常量是静态final实例。

```java
public enum Status {
    PENDING,       // 相当于 public static final Status PENDING = new Status();
    SUCCESS,
    FAILED;
}
```

**枚举与switch：** 枚举天生适合switch，编译期类型安全检查，代码更清晰。

```java
OrderStatus status = OrderStatus.PENDING;
switch (status) {
    case PENDING: break;
    case PAID: break;
    case SHIPPED: break;
}
```

**高级用法：**

```java
// 带字段和构造方法
public enum OrderStatus {
    PENDING(0, "待支付"),
    PAID(1, "已支付"),
    SHIPPED(2, "已发货");

    private final int code;
    private final String desc;

    OrderStatus(int code, String desc) {
        this.code = code;
        this.desc = desc;
    }

    // 根据code查询
    public static OrderStatus fromCode(int code) {
        for (OrderStatus s : values()) {
            if (s.code == code) return s;
        }
        throw new IllegalArgumentException();
    }
}
```

**应用场景：**
- 枚举实现**单例模式**（最安全，防止反射和序列化破坏）
- 枚举实现**策略模式**（每个枚举常量实现抽象方法）
- 枚举替代常量类，**类型安全**，编译期检查

# 11. 深浅克隆

浅克隆和深克隆的区别？如何实现深克隆？

**浅克隆：** 复制对象本身，内部引用类型字段仍指向原对象。实现 `Cloneable` 接口 + 重写 clone()。

```java
class User implements Cloneable {
    String name;
    Address address;  // 引用类型

    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone();  // 浅克隆，address指向同一个
    }
}
```

**深克隆：** 复制对象和所有引用类型字段指向的对象。

```java
// 方式1：重写clone递归克隆
@Override
protected Object clone() throws CloneNotSupportedException {
    User user = (User) super.clone();
    user.address = (Address) address.clone();  // 递归克隆
    return user;
}

// 方式2：序列化（推荐，但需实现Serializable）
User deepClone(User user) {
    ByteArrayOutputStream bos = new ByteArrayOutputStream();
    ObjectOutputStream oos = new ObjectOutputStream(bos);
    oos.writeObject(user);

    ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
    ObjectInputStream ois = new ObjectInputStream(bis);
    return (User) ois.readObject();
}
```

# 12. 序列化

Java序列化的原理是什么？serialVersionUID和transient的作用？

**序列化原理：** 将Java对象转换为字节序列（二进制），便于存储或网络传输。通过 `ObjectOutputStream` 写对象，`ObjectInputStream` 读对象。

```java
// 序列化
ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("user.ser"));
oos.writeObject(user);
oos.close();

// 反序列化
ObjectInputStream ois = new ObjectInputStream(new FileInputStream("user.ser"));
User user = (User) ois.readObject();
ois.close();
```

**Serializable接口：** 标记接口，没有方法，告诉JVM该类可以序列化。

```java
public class User implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private transient String password;
}
```

**serialVersionUID：**
- 序列化版本号，用于反序列化时验证类的兼容性
- 如果不显式声明，JVM会根据类结构自动生成
- 类结构变化（增减字段）后自动生成的值会变，导致反序列化失败
- **建议显式声明**：`private static final long serialVersionUID = 1L;`

**transient关键字：**
- 修饰的字段**不参与序列化**，反序列化后为默认值（对象为null，基本类型为0/false）
- 适用于敏感信息（密码）、无需序列化的字段（缓存数据）

**Externalizable接口：**
- 继承自Serializable，提供更精细的控制
- 需要实现 `writeExternal()` 和 `readExternal()` 方法，自定义序列化逻辑
- 序列化时不调用默认机制，完全由自定义方法控制

```java
public class User implements Externalizable {
    private String name;
    private String password;

    @Override
    public void writeExternal(ObjectOutput out) throws IOException {
        out.writeObject(name);
    }

    @Override
    public void readExternal(ObjectInput in) throws IOException, ClassNotFoundException {
        name = (String) in.readObject();
    }
}
```

**注意事项：**
- 静态变量不参与序列化（属于类，不属于对象）
- 序列化会破坏**单例模式**（反序列化时创建新对象），通过 `readResolve()` 方法保护
- 父类实现了Serializable，子类自动可序列化
- 反序列化时不调用构造器，直接由字节数据恢复对象

# 13. String相关高频问题

String、StringBuilder、StringBuffer的区别？String的不可变性如何实现？

**三者的区别：**

| 特性 | String | StringBuilder | StringBuffer |
|------|--------|---------------|-------------|
| 可变性 | 不可变 | 可变 | 可变 |
| 线程安全 | 安全（不可变） | 不安全 | 安全（synchronized） |
| 性能 | 拼接产生新对象 | 快 | 慢（有同步） |
| 适用 | 少量字符串/常量 | 单线程大量拼接 | 多线程字符串操作 |

**String不可变性：**

```java
public final class String {
    private final char value[];  // final数组 + private不暴露
    // 所有修改方法（concat, replace等）都返回新String对象
}
```

通过final修饰类（禁止继承）、final修饰char数组（引用不可变）、不暴露内部数组实现不可变性。

**String常量池：**

- JDK7之前在方法区（永久代），JDK7移到堆
- `String s1 = "hello";` 从常量池获取，池中没有则创建
- `String s2 = new String("hello");` 堆上创建新对象，但常量池中也可能有
- `intern()` 将字符串放入常量池并返回池中引用

```java
String s1 = "hello";
String s2 = "hello";
String s3 = new String("hello");
String s4 = s3.intern();

System.out.println(s1 == s2); // true（常量池同一对象）
System.out.println(s1 == s3); // false（堆上新对象）
System.out.println(s1 == s4); // true（intern返回池中引用）
```

**Switch对String的支持：** Java7开始switch支持String，编译时用hashCode比较。
