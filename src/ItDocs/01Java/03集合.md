# 1. HashMap的底层实现原理

HashMap的底层实现原理是什么？JDK7和JDK8有什么区别？
**原理分析**
**JDK7 vs JDK8 区别：**
| 特性 | JDK7 | JDK8 |
|-----|------|------|
| 数据结构 | 数组+链表 | 数组+链表+**红黑树** |
| 哈希冲突 | 链表 | 链表→红黑树（链表长度≥**8**） |
| 插入方式 | 头插法 | 尾插法 |
| 扩容 | 重新hash | 原位置或原位置+旧容量 |
| 扰动 | 2次 | 1次 |
**JDK8 HashMap结构：**
```java
transient Node<K,V>[] table;
static class Node<K,V> implements Map.Entry<K,V> {
    final int hash;
    final K key;
    V value;
    Node<K,V> next;
}
```
**put流程：**
```java
public V put(K key, V value) {
    return putVal(hash(key), key, value, false, true);
}
final V putVal(int hash, K key, V value, boolean onlyIfAbsent, boolean evict) {
    Node<K,V>[] tab; Node<K,V> p; int n, i;
    // 1. 初始化
    if ((tab = table) == null || (n = tab.length) == 0)
        n = (tab = resize()).length;
    // 2. 计算位置
    if ((p = tab[i = (n - 1) & hash]) == null)
        tab[i] = newNode(hash, key, value, null);
    else {
        Node<K,V> e; K k;
        // 3. key相同，覆盖
        if (p.hash == hash && ((k = p.key) == key || (key != null && key.equals(k))))
            e = p;
        // 4. 红黑树插入
        else if (p instanceof TreeNode)
            e = ((TreeNode<K,V>)p).putTreeVal(this, tab, hash, key, value);
        // 5. 链表插入
        else {
            for (int binCount = 0; ; ++binCount) {
                if ((e = p.next) == null) {
                    p.next = newNode(hash, key, value, null);
                    if (binCount >= TREEIFY_THRESHOLD - 1)
                        treeifyBin(tab, hash);
                    break;
                }
                if (e.hash == hash &&
                    ((k = e.key) == key || (key != null && key.equals(k))))
                    break;
                p = e;
            }
        }
        // 6. 找到相同key，覆盖value并返回oldValue
        if (e != null) {
            V oldValue = e.value;
            if (!onlyIfAbsent || oldValue == null)
                e.value = value;
            afterNodeAccess(e);
            return oldValue;
        }
    }
    ++modCount;
    if (++size > threshold)
        resize();
    afterNodeInsertion(evict);
    return null;
}
```
> HashMap为什么容量是2的幂？
```java
// 计算位置
index = (n - 1) & hash
// n是2的幂时，(n-1)的二进制全是1
// 等价于 hash % n，但位运算更快
```
# 2. ConcurrentHashMap的原理与JDK8的优化

ConcurrentHashMap的原理是什么？JDK7和JDK8有什么区别？
**原理分析**
**JDK7 vs JDK8 区别：**
| 特性 | JDK7 | JDK8 |
|-----|------|------|
| 数据结构 | Segment数组+HashEntry数组+链表 | **Node数组**+链表+红黑树 |
| 并发粒度 | Segment（继承ReentrantLock） | **Node**（CAS+synchronized） |
| 锁数量 | 16个Segment | 数组长度 |
| 锁方式 | 继承ReentrantLock的Segment | **synchronized + CAS** |
**JDK8 ConcurrentHashMap：**
```java
transient volatile Node<K,V>[] table;
static class Node<K,V> implements Map.Entry<K,V> {
    final int hash;
    final K key;
    volatile V value;
    volatile Node<K,V> next;
}
```
**put流程：**
```java
final V putVal(K key, V value, boolean onlyIfAbsent) {
    if (key == null || value == null) throw new NullPointerException();
    int hash = spread(key.hashCode());
    for (Node<K,V>[] tab = table;;) {
        // 1. 初始化
        if (tab == null || (n = tab.length) == 0)
            tab = initTable();
        // 2. 空位，CAS插入
        else if ((f = tabAt(tab, i = (n - 1) & hash)) == null) {
            if (casTabAt(tab, i, null, new Node<K,V>(hash, key, value, null)))
                break;
        }
        // 3. 扩容协助
        else if ((fh = f.hash) == MOVED)
            tab = helpTransfer(tab, f);
        // 4. 同步插入
        else {
            synchronized (f) {
                // 链表/红黑树插入
            }
        }
    }
}
```
> ConcurrentHashMap为什么放弃Segment？
1. **内存占用**：Segment继承ReentrantLock，有额外开销
2. **复杂度**：分段锁需要两次哈希定位
3. **粒度**：JDK8使用更细粒度的synchronized+CAS，性能更好
# 3. HashMap的线程安全问题与解决方案

HashMap是线程安全的吗？多线程环境下使用HashMap会有什么问题？
**原理分析**
**线程不安全原因：**
1. **并发put导致数据丢失**：
```java
// 线程A: 计算hash=5，准备插入
// 线程B: 计算hash=5，准备插入
// 线程A: put成功
// 线程B: put成功，覆盖A的值
```
2. **resize时出现死循环**（JDK7头插法）：
```java
// JDK7 resize
void transfer(Entry[] newTable) {
    for (Entry<K,V> e : src) {
        do {
            Entry<K,V> next = e.next;
            e.next = newTable[i];
            newTable[i] = e;
            e = next;
        } while (e != null);
    }
}
// 并发resize导致环形链表，get时死循环
```
3. **可见性问题**：
```java
HashMap map = new HashMap();
map.put("key", "value");
// 线程B读取可能为null
```
**解决方案：**
```java
// 1. ConcurrentHashMap
ConcurrentHashMap<Integer, Integer> map = new ConcurrentHashMap<>();
// 2. Collections.synchronizedMap
Map<Integer, Integer> map = Collections.synchronizedMap(new HashMap<>());
// 3. Hashtable（不推荐，性能差）
Hashtable<Integer, Integer> map = new Hashtable<>();
```
> Collections.synchronizedMap的实现原理？
所有方法都使用synchronized包裹同一个mutex对象。
# 4. HashMap的扩容机制与阈值计算

HashMap的扩容机制是怎样的？扩容阈值如何计算？
**原理分析**
**触发条件：**
1. 元素数量 > **threshold**（capacity * loadFactor）
2. 链表长度 >= TREEIFY_THRESHOLD（8），且数组长度 < 64
**默认参数：**
```java
static final int DEFAULT_INITIAL_CAPACITY = 1 << 4;    // 16
static final float DEFAULT_LOAD_FACTOR = 0.75f;
static final int TREEIFY_THRESHOLD = 8;
static final int MIN_TREEIFY_CAPACITY = 64;
```
**threshold计算：**
```java
this.threshold = tableSizeFor(initialCapacity);
// tableSizeFor：返回>=cap的最小2的幂
static final int tableSizeFor(int cap) {
    int n = cap - 1;
    n |= n >>> 1;
    n |= n >>> 2;
    n |= n >>> 4;
    n |= n >>> 8;
    n |= n >>> 16;
    return (n < 0) ? 1 : (n >= MAXIMUM_CAPACITY) ? MAXIMUM_CAPACITY : n + 1;
}
```
**扩容流程：**
```java
final Node<K,V>[] resize() {
    Node<K,V>[] oldTab = table;
    int oldCap = oldTab == null ? 0 : oldTab.length;
    int oldThr = threshold;
    int newCap, newThr = 0;
    if (oldCap > 0) {
        if (oldCap >= MAXIMUM_CAPACITY) {
            threshold = Integer.MAX_VALUE;
            return oldTab;
        }
        else if ((newCap = oldCap << 1) < MAXIMUM_CAPACITY)
            newThr = oldThr << 1;
    }
    // 迁移元素：原位置或原位置+旧容量
    // e.hash & oldCap 判断是否需要移动
}
```
> 负载因子为什么是0.75？
- **0.5**：扩容频繁，空间利用率低
- **0.75**：平衡点，扩容后约75%利用率
- **1.0**：空间利用率高，但冲突增多，性能下降

# 6. ConcurrentHashMap的get方法无锁原理

ConcurrentHashMap的get方法为什么不需要加锁？它是如何保证可见性的？
**原理分析**
**无锁get原理：**
```java
public V get(Object key) {
    Node<K,V>[] tab; Node<K,V> e, p; int n, i, eh;
    int h = spread(key.hashCode());
    if ((tab = table) != null && (n = tab.length) > 0 &&
        (e = tabAt(tab, i = (n - 1) & h)) != null) {
        if ((eh = e.hash) == h) {
            if ((ek = e.key) == key || (ek != null && key.equals(ek)))
                return e.value;
        }
        else if (eh < 0)
            return (p = e.find(h, key)) != null ? p.value : null;
        while ((e = e.next) != null) {
            if (e.hash == h && ((ek = e.key) == key || (ek != null && key.equals(ek))))
                return e.value;
        }
    }
    return null;
}
```
**可见性保证：**
1. **volatile value**：
```java
static class Node<K,V> {
    volatile V value;  // volatile保证可见性
}
```
2. **tabAt使用getObjectVolatile**：
```java
static final <K,V> Node<K,V> tabAt(Node<K,V>[] tab, int i) {
    return (Node<K,V>)U.getObjectVolatile(tab, ...);
}
```
> ConcurrentHashMap的get和put可以同时进行吗？
可以：
- get读的是已经存在的节点
- put如果该位置为null，CAS写入
- 如果该位置有节点，synchronized锁住该节点进行修改
# 7. 红黑树的特性与HashMap中的实现

红黑树有哪些特性？HashMap中的红黑树是如何实现的？
**原理分析**
**红黑树特性：**
1. 节点是红色或黑色
2. 根节点是黑色
3. 叶子节点（NIL）是黑色
4. **红节点的子节点必须是黑色**
5. **任意节点到每个叶子节点的路径包含相同数量的黑节点**
**平衡操作：**
```java
// 左旋
static <K,V> TreeNode<K,V> rotateLeft(TreeNode<K,V> root, TreeNode<K,V> p) {
    TreeNode<K,V> r = p.right;
    p.right = r.left;
    if (r.left != null) r.left.parent = p;
    r.parent = p.parent;
    if (p.parent == null) root = r;
    else if (p.parent.left == p) p.parent.left = r;
    else p.parent.right = r;
    r.left = p;
    p.parent = r;
    return root;
}
```
**插入调整：**
每次插入后需要**重新着色和旋转**来保持平衡。
> 红黑树与AVL树的区别？
| 特性 | 红黑树 | AVL树 |
|-----|-------|------|
| 平衡度 | 黑高平衡 | 严格平衡（左右高度差≤1） |
| 插入/删除开销 | O(1)旋转 | O(logN)旋转 |
| 查询性能 | 略差于AVL | 最优 |
# 8. CopyOnWriteArrayList的原理与适用场景

CopyOnWriteArrayList的原理是什么？它适合什么场景？
**原理分析**
**核心思想：**
写操作时复制整个数组，读取不需要加锁。
```java
private transient volatile Object[] array;
// 读操作
public E get(int index) {
    return getAt(array, index);
}
// 写操作：加锁+复制
public boolean add(E e) {
    synchronized (lock) {
        Object[] elements = getArray();
        Object[] newElements = Arrays.copyOf(elements, len + 1);
        newElements[len] = e;
        setArray(newElements);
    }
}
```
**特性：**
| 特性 | 说明 |
|-----|------|
| 读写分离 | 读无锁，写加锁 |
| 最终一致性 | 写操作后读可能读到旧数据 |
| 内存占用 | 每次写都复制，内存占用高 |
| 适用场景 | **读多写少**（配置、缓存） |
> CopyOnWriteArrayList的迭代器特性？
迭代器不会抛出**ConcurrentModificationException**，因为迭代器遍历的是创建迭代器时的数组快照。
# 9. HashMap的hash方法扰动设计

HashMap的hash方法是如何实现的？为什么要这样设计？
**原理分析**
**JDK8 hash方法：**
```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 :
        (h = key.hashCode()) ^ (h >>> 16);
}
```
**为什么这样做：**
1. **扰动**：高16位与低16位异或，让hash更分散
```
原始hash: 11111111 11111111 11111111 11111111
高16位:   11111111 11111111
低16位:   11111111 11111111
异或后:   00000000 00000000 11111111 11111111
```
2. **与运算优化**：
```java
// n是2的幂，hash & (n-1) 等价于 hash % n
// 扰动后分散了高16位信息
```
3. **解决负数问题**：
```java
index = (n - 1) & hash;
// 结果始终在 [0, n-1] 范围内
```
> 扰动为什么用异或而不是与/或？
**异或的特性**：
- 相同为0，不同为1
- 可逆：a ^ b ^ b = a
- 混合高位和低位信息，让结果更分散
# 10. ConcurrentHashMap的多线程扩容机制

ConcurrentHashMap是如何进行扩容的？多线程如何协助扩容？
**原理分析**
**触发条件：**
```java
// 元素数量 > 阈值
while (s >= (long)(sc = sizeCtl) && (tab = table) != null) {
    if (tab.length < MAXIMUM_CAPACITY)
        transfer(tab, nextTab);
}
```
**transfer流程：**
```java
private final void transfer(Node<K,V>[] tab, Node<K,V>[] nextTab) {
    int n = tab.length, stride;
    // 步长：每个线程处理至少16个桶
    stride = (n >>> 3) / NCPU;
    if (stride < MINIMUM_TRANSFER_STRIDE)
        stride = MINIMUM_TRANSFER_STRIDE;
    // 第一个线程创建新数组
    if (nextTab == null) {
        nextTab = new Node[n << 1];
    }
    for (int i = 0; i < n; i++) {
        for (Node<K,V> f = tabAt(tab, i); f != null; ) {
            if (f.hash == MOVED) {
                // 已经是ForwardingNode，帮助迁移
                tab = helpTransfer(tab, f);
            } else {
                synchronized (f) {
                    // 迁移单个桶
                }
            }
        }
    }
}
```
**ForwardingNode：**
```java
static final class ForwardingNode<K,V> extends Node<K,V> {
    final Node<K,V>[] nextTable;
    // find方法：去新数组查找
}
```
> 多线程如何协助扩容？
```java
// 线程A在put时发现正在扩容
else if ((fh = f.hash) == MOVED)
    tab = helpTransfer(tab, f);
final Node<K,V>[] helpTransfer(Node<K,V>[] tab, Node<K,V> f) {
    Node<K,V>[] nextTab = f.nextTable;
    if (nextTab != null) transfer(tab, nextTab);
    return nextTab;
}
```
帮助迁移的线程会参与扩容工作，加速扩容完成。
# 11. HashMap为什么容量必须是2的幂次方？

HashMap为什么要求容量必须是2的幂次方？这样做的好处是什么？
**原理分析**
**计算索引的方式：**
```java
index = (n - 1) & hash
```
当n为2的幂次方时，`n-1`的二进制形式全是1：
- n = 16 (10000)，n-1 = 15 (01111)
- n = 32 (100000)，n-1 = 31 (011111)
**好处：**
1. **位运算代替取模**：
   ```java
   hash % n  →  (n-1) & hash
   ```
   位运算比取模快很多倍
2. **分布均匀**：
   ```
   n-1 = 01111 (15)
   hash = 10010110 (150)
   150 & 15 = 6  (分布均匀)
   ```
3. **扩容时便于迁移**：
   ```java
   // 只需判断hash的第n位
   newIndex = (hash & oldCap) == 0 ? oldIndex : oldIndex + oldCap
   ```
   只需判断hash的特定位是0还是1，决定放在原位置还是原位置+oldCap
**如果不是2的幂次方：**
```java
// n = 15 (01111)，capacity = 15
hash = 10010110 (150)
150 & 14 = 6  // 0110
// 但15的二进制是0111，少了最高位的1
// 导致某些位置永远无法命中，分布不均匀
```
> 如果手动指定容量不是2的幂次方会怎样？
```java
new HashMap<>(10);  // 实际容量是16
new HashMap<>(15);  // 实际容量是16
new HashMap<>(17);  // 实际容量是32
```
HashMap会自动调整为最近的2的幂次方：`tableSizeFor(17) = 32`
# 12. HashMap遍历方式有哪些？哪种最优？

HashMap有哪些遍历方式？各自的特点是什么？
**原理分析**
**4种遍历方式：**
```java
Map<Integer, String> map = new HashMap<>();
for (int i = 0; i < 100; i++) map.put(i, "value" + i);
// 1. keySet遍历（不推荐）
for (Integer key : map.keySet()) {
    String value = map.get(key);  // 每次get需要再计算hash
}
// 2. entrySet遍历（推荐）
for (Map.Entry<Integer, String> entry : map.entrySet()) {
    Integer key = entry.getKey();
    String value = entry.getValue();
}
// 3. Iterator遍历
Iterator<Map.Entry<Integer, String>> it = map.entrySet().iterator();
while (it.hasNext()) {
    Map.Entry<Integer, String> entry = it.next();
}
// 4. Lambda遍历（JDK8+）
map.forEach((k, v) -> System.out.println(k + "=" + v));
```
**性能对比：**
| 方式 | 时间复杂度 | 额外开销 | 推荐 |
|-----|-----------|---------|------|
| keySet + get | O(n*k) | 每次重新计算hash | 不推荐 |
| entrySet | O(n) | 一次遍历 | **推荐** |
| Iterator | O(n) | 迭代器对象 | 推荐 |
| forEach | O(n) | Lambda开销 | 小数据量推荐 |
**最佳实践：**
```java
// 推荐：使用entrySet
for (Map.Entry<K, V> entry : map.entrySet()) {
    K key = entry.getKey();
    V value = entry.getValue();
}
```
> 为什么keySet不推荐？
因为`map.get(key)`需要再次计算hash并查找，额外开销大：
```java
public V get(Object key) {
    Node<K,V> e;
    return (e = getNode(hash(key), key)) == null ? null : e.value;
}
```
# 13. Hashtable与ConcurrentHashMap的区别

Hashtable与ConcurrentHashMap有什么区别？为什么推荐使用ConcurrentHashMap？
**原理分析**
**区别对比：**

public synchronized V put(K key, V value) { ... }
public synchronized V remove(Object key) { ... }

```
**ConcurrentHashMap实现：**
```java
// JDK8
public V get(Object key) {
    Node<K,V>[] tab; Node<K,V> e, p; int n, i, h;
    // 无锁读，利用volatile保证可见性
}
public V put(K key, V value) {
    // CAS + synchronized实现
    // 只锁定单个桶，其他桶可以并发操作
}
```
**性能对比：**
```java
// 1000个线程并发写入
Hashtable:      ~5000ms
ConcurrentHashMap: ~200ms  // 25倍性能提升
```
**迭代器区别：**
```java
// Hashtable：强一致性，遍历期间不允许修改
// ConcurrentHashMap：弱一致性，遍历期间可以修改

> 为什么ConcurrentHashMap不允许null？
为了避免歧义：
- null.get() 返回null，是"不存在"还是"值就是null"？
- 统一禁止null，避免歧义
# 14. HashSet的底层实现

HashSet的底层实现是什么？它与HashMap有什么区别？
**原理分析**
**HashSet实现：**
```java
public class HashSet<E> extends AbstractSet<E> implements Set<E>, Cloneable, Serializable {
    private transient HashMap<E, Object> map;
    private static final Object PRESENT = new Object();  // 统一的value
    public HashSet() {
        map = new HashMap<>();
    }
    public boolean add(E e) {
        return map.put(e, PRESENT) == null;
    }
    public boolean contains(Object o) {
        return map.containsKey(o);
    }
    public boolean remove(Object o) {
        return map.remove(o) != null;
    }
}
```
**实际上HashSet内部是一个HashMap**，所有元素作为key，value使用一个统一的空对象PRESENT。
**HashSet vs HashMap：**
| 特性 | HashSet | HashMap |
|-----|---------|---------|
| 底层 | HashMap（value统一为PRESENT） | 数组+链表+红黑树 |
| 唯一性 | 保证元素不重复 | key唯一 |
| 允许null | 允许一个null | 允许一个null key |
| 线程安全 | 不安全 | 不安全 |
**LinkedHashSet：**
```java
// 维护一个双向链表，保持插入顺序
public class LinkedHashSet<E> extends HashSet<E> implements Set<E> {
    // 继承HashSet，使用LinkedHashMap
}
```
**TreeSet：**
```java
// 基于TreeMap实现，内部是红黑树
public class TreeSet<E> extends AbstractSet<E> implements NavigableSet<E> {
    private transient NavigableMap<E,Object> m;
    // 底层是TreeMap
}
```
> HashSet如何保证元素唯一性？
利用HashMap的key唯一性：
```java
public boolean add(E e) {
    return map.put(e, PRESENT) == null;  // null表示新插入
}
```
# 15. TreeMap的底层实现与排序

TreeMap的底层实现是什么？它如何保证key的有序性？
**原理分析**
**TreeMap实现：**
```java
public class TreeMap<K,V> extends AbstractMap<K,V> implements NavigableMap<K,V> {
    private final Comparator<? super K> comparator;
    private transient Entry<K,V> root;
    static final class Entry<K,V> implements Map.Entry<K,V> {
        K key;
        V value;
        Entry<K,V> left;
        Entry<K,V> right;
        Entry<K,V> parent;
        boolean color = BLACK;
    }
}
```
**底层是红黑树**，与HashMap中的TreeNode相同。
**put操作：**
```java
public V put(K key, V value) {
    Entry<K,V> t = root;
    if (t == null) {
        compare(key, key);  // 类型检查
        root = new Entry<>(key, value, null);
        size = 1;
        return null;
    }
    int cmp;
    Entry<K,V> parent;
    // 按Comparator比较查找位置
    do {
        parent = t;
        cmp = compare(key, t.key);
        if (cmp < 0) t = t.left;
        else if (cmp > 0) t = t.right;
        else return setValue(value);
    } while (t != null);
    Entry<K,V> e = new Entry<>(key, value, parent);
    if (cmp < 0) parent.left = e;
    else parent.right = e;
    fixAfterInsertion(e);  // 保持红黑树平衡
    return null;
}
```
**与HashMap的区别：**
| 特性 | TreeMap | HashMap |
|-----|---------|---------|
| 底层 | 红黑树 | 数组+链表+红黑树 |
| 顺序 | 有序（按key排序） | 无序 |
| 时间复杂度 | O(logN) | O(1)平均 |
| 插入/查找 | O(logN) | O(1)平均 |
| 适用场景 | 需要排序 | 需要快速查找 |
**Comparator vs Comparable：**
```java
// 使用Comparator
TreeMap<Person, String> map = new TreeMap<>(new Comparator<Person>() {
    @Override
    public int compare(Person p1, Person p2) {
        return p1.age - p2.age;  // 按年龄排序
    }
});
// 使用Comparable（让Person实现Comparable）
class Person implements Comparable<Person> {
    int age;
    @Override
    public int compareTo(Person p) {
        return this.age - p.age;
    }
}
```
> TreeMap的 ceilingKey、floorKey 方法？
```java
// 大于等于key的最小key
map.ceilingKey(key);
// 小于等于key的最大key
map.floorKey(key);
```
# 16. LinkedHashMap的原理

LinkedHashMap的原理是什么？它与HashMap有什么区别？
**原理分析**
**LinkedHashMap实现：**
```java
public class LinkedHashMap<K,V> extends HashMap<K,V> {
    // 双向链表头结点
    transient LinkedHashMap.Entry<K,V> head;
    transient LinkedHashMap.Entry<K,V> tail;
    // 节点继承HashMap.Node，增加了前后指针
    static class Entry<K,V> extends HashMap.Node<K,V> {
        LinkedHashMap.Entry<K,V> before, after;
        Entry(int hash, K key, V value, Node<K,V> next) {
            super(hash, key, value, next);
        }
    }
}
```
**继承HashMap**，但内部维护一个**双向链表**来保持插入顺序。
**两种顺序：**
```java
// 插入顺序（默认）
LinkedHashMap<Integer, String> map = new LinkedHashMap<>();
map.put(1, "a");
map.put(2, "b");
map.put(3, "c");
// 遍历：1->a, 2->b, 3->c
// 访问顺序（LRU缓存）
LinkedHashMap<Integer, String> map = new LinkedHashMap<>(16, 0.75f, true);
map.get(1);  // 访问后移到末尾
```
**LRU缓存实现：**
```java
class LRUCache extends LinkedHashMap<Integer, String> {
    private final int capacity;
    public LRUCache(int capacity) {
        super(16, 0.75f, true);
        this.capacity = capacity;
    }
    @Override
    protected boolean removeEldestEntry(Map.Entry<Integer, String> eldest) {
        return size() > capacity;  // 超过容量删除最老的
    }
}
```
**与HashMap的区别：**
| 特性 | LinkedHashMap | HashMap |
|-----|--------------|---------|
| 顺序 | 维护双向链表 | 无序 |
| 内存 | 额外指针开销 | 较小 |
| 遍历 | 按插入/访问顺序 | 随机 |
| 适用场景 | LRU缓存、保持顺序 | 快速查找 |
> LinkedHashMap如何实现LRU？
重写`removeEldestEntry`方法：
```java
@Override
protected boolean removeEldestEntry(Map.Entry eldest) {
    return size() > MAX_SIZE;
}
```

**size方法实现：**

final long sumCount() {
    CounterCell[] cells = counterCells;

            if (cell != null) {

            }
        }
    }

}
```

# 18. Map遍历时如何安全地删除元素？

如何在遍历Map时安全地删除元素？
**原理分析**
**错误方式：**
```java
// ConcurrentModificationException
for (Map.Entry<Integer, String> entry : map.entrySet()) {
    if (entry.getValue().equals("delete")) {
        map.remove(entry.getKey());  // 会抛异常
    }
}
// 迭代过程中修改
Iterator<Map.Entry<Integer, String>> it = map.entrySet().iterator();
while (it.hasNext()) {
    Map.Entry<Integer, String> entry = it.next();
    if (entry.getValue().equals("delete")) {
        map.remove(entry.getKey());  // 会抛异常
    }
}
```
**正确方式1：使用Iterator.remove()**
```java
Iterator<Map.Entry<Integer, String>> it = map.entrySet().iterator();
while (it.hasNext()) {
    Map.Entry<Integer, String> entry = it.next();
    if (entry.getValue().equals("delete")) {
        it.remove();  // 使用迭代器的remove
    }
}
```
**正确方式2：使用removeIf（JDK8+）**
```java
map.entrySet().removeIf(entry -> entry.getValue().equals("delete"));
```
**正确方式3：HashMap使用keySet.remove()**
```java
for (Integer key : new ArrayList<>(map.keySet())) {
    if (map.get(key).equals("delete")) {
        map.remove(key);  // 先复制key再删除
    }
}
```
**正确方式4：ConcurrentHashMap安全遍历**
```java
// ConcurrentHashMap可以安全在遍历时删除
for (Map.Entry<Integer, String> entry : map.entrySet()) {
    if (entry.getValue().equals("delete")) {
        map.remove(entry.getKey());  // 不会抛异常
    }
}
```
**原理：**
- HashMap：遍历时modCount会变化，检测到则抛异常
- Iterator.remove()：先修改modCount，再从链表删除
- ConcurrentHashMap：使用弱一致的迭代器，不检测modCount
> Iterator.remove()的原理？
```java
public final void remove() {
    Node<K,V> p = current;
    if (p == null)
        throw new IllegalStateException();
    if (modCount != expectedModCount)
        throw new ConcurrentModificationException();
    current = null;
    removeNode(p.hash, p.key, null, false, false);
    expectedModCount = modCount;
}
```
# 19. List、Set、Map三者的核心区别

List、Set、Map三者的核心区别是什么？
**原理分析**
- **List**：有序（按插入顺序），允许重复元素，允许多个null
- **Set**：无序（部分实现有序如TreeSet/LinkedHashSet），**不允许重复**，最多允许一个null
- **Map**：键值对存储，**key不允许重复**，key最多允许一个null（HashMap），值可以多个null
**判断重复标准：**
- List：equals()判断，不限制重复
- Set：equals()判断，重复则不插入
- Map：key的equals()判断，重复则覆盖value
**线程安全实现：**
- List：CopyOnWriteArrayList、Vector
- Set：CopyOnWriteArraySet、ConcurrentHashMap.newKeySet()
- Map：ConcurrentHashMap、ConcurrentSkipListMap
> TreeSet如何保证有序？
底层是TreeMap，使用红黑树结构，默认按key的自然顺序排序，也可传入自定义Comparator。
# 20. fail-fast机制的原理与解决方案

什么是fail-fast机制？如何解决遍历集合时抛ConcurrentModificationException？
**原理分析**
**定义：**
fail-fast是Java集合的**错误检测机制**，当多个线程对集合进行结构性修改时，或单线程遍历时违反规则修改集合，会立即抛出ConcurrentModificationException。
**原理：**
- 集合内部维护一个**modCount**变量记录结构性修改次数
- 迭代器初始化时记录expectedModCount = modCount
- 每次调用next()/hasNext()时检查modCount是否等于expectedModCount
- 不相等则抛ConcurrentModificationException
**触发场景：**
```java
// 单线程：遍历时修改
for (String s : list) {
    if ("xxx".equals(s)) {
        list.remove(s);  // ❌ ConcurrentModificationException
    }
}
// 多线程：一个线程遍历，另一个线程修改
```
**解决方案：**
1. **使用Iterator.remove()**：
```java
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if ("xxx".equals(it.next())) {
        it.remove();  // ✅ 同步expectedModCount
    }
}
```
2. **使用CopyOnWriteArrayList**：
遍历的是快照，修改不影响遍历
3. **使用ConcurrentHashMap**：
弱一致性迭代器，不检测modCount
4. **加锁同步**：
所有修改操作加synchronized
> removeIf的原理？
JDK8的Collection.removeIf内部使用Iterator遍历并调用remove()，不会抛异常：
```java
list.removeIf(s -> s.equals("xxx"));
```

# 22. 为什么重写equals必须重写hashCode

为什么重写equals时必须重写hashCode？不重写会有什么问题？
**原理分析**
**hashCode与equals的约定：**
1. **equals相等，hashCode一定相等**（反过来说，如果hashCode不相等，equals一定不相等）
2. **hashCode相等，equals不一定相等**（哈希冲突）
**只重写equals的问题：**
```java
class Person {
    String id;
    public boolean equals(Object o) {
        return id.equals(((Person)o).id);  // 按id相等
    }
    // 没重写hashCode，使用Object默认的（内存地址）
}
Map<Person, String> map = new HashMap<>();
map.put(new Person("1"), "a");
map.get(new Person("1"));  // null ❌
// 两个Person("1") equals相等，但hashCode不同
// 所以定位到不同桶，get找不到
```
**只重写hashCode的问题：**
```java
class Person {
    String id;
    public int hashCode() { return id.hashCode(); }
    // 没重写equals，使用Object默认的（==比较）
}
Map<Person, String> map = new HashMap<>();
map.put(new Person("1"), "a");
map.put(new Person("1"), "b");  // 不会覆盖，因为==不相等
map.size();  // 2 ❌ 出现重复key
```
**总结：**
- HashMap/HashSet依赖hashCode定位桶，依赖equals判断key是否相同
- 两者必须同时重写，保证逻辑相等的对象hashCode也相等
- 如果确定对象不会放入Hash集合，可以不重写hashCode
> hashCode()方法的设计原则？
1. **一致性**：同一对象多次调用返回相同值
2. **equals相等则hashCode相等**
3. **hashCode尽量分散**，减少碰撞
# 23. 自定义类作为HashMap的key需要注意什么

如果让你实现一个自定义的class作为HashMap的key，需要注意什么？
**原理分析**
**必须重写equals和hashCode**：
```java
public class User {
    private Long id;
    private String name;
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        User user = (User) o;
        return Objects.equals(id, user.id);
    }
    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}
```
**最佳实践：**
1. **不可变性**：key最好是**不可变对象**，一旦放入HashMap后不要修改其属性
```java
User user = new User(1, "a");
map.put(user, "value");
user.setId(2);  // ❌ hashcode变了，再也找不到这个key
```
2. **equals和hashCode使用相同的属性字段**，且是业务唯一标识
3. **避免使用可变字段**参与hashCode计算
4. **推荐使用String、Integer等JDK不可变类**作为key
> 如果必须使用可变对象作为key怎么办？
- 确保放入后不再修改hashCode相关的字段
- 或改用TreeMap（依赖Comparator，不依赖hashCode）
# 24. HashMap的hash冲突解决方案

HashMap是如何解决hash冲突的？有哪些措施？
**原理分析**
**三种措施：**
1. **链地址法（拉链法）**：
数组每个位置是一个链表（或红黑树），冲突的元素挂在同一个桶的链表上
2. **扰动函数**：
```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```
高16位与低16位异或，让散列更均匀，减少冲突概率
3. **红黑树优化**：
当链表长度 >= 8 且数组长度 >= 64，链表转为红黑树，查询从O(n)降为O(logN)
**开放地址法（ThreadLocalMap使用）**：
冲突时找下一个空位，线性探测或二次探测。HashMap不使用这种方法。
> 为什么HashMap采用链地址法而不是开放地址法？
链地址法处理冲突简单，平均查找长度较短，删除方便。开放地址法容易产生堆积，删除需要惰性删除，不适合HashMap这种频繁增删的场景。
# 25. JDK7头插法为何改为JDK8尾插法

为什么JDK8将HashMap的链表插入方式从头插法改为尾插法？
**原理分析**
**JDK7头插法：**
- 新节点插入链表头部
- 扩容时transfer方法会**反转链表顺序**
```java
void transfer(Entry[] newTable) {
    for (Entry<K,V> e : src) {
        Entry<K,V> next = e.next;
        e.next = newTable[i];  // 头插
        newTable[i] = e;
        e = next;
    }
}
```
- 多线程扩容时，可能**形成环形链表**，导致get死循环
**JDK8尾插法：**
- 新节点插入链表尾部
- 扩容时保持原链表顺序
- **解决了死循环问题**，但HashMap仍然非线程安全
**为什么JDK7用头插法？**
头插法不需要遍历链表，插入效率更高。但JDK7未考虑并发场景。
> JDK8改用尾插法后HashMap就线程安全了吗？
不是。尾插法只解决了扩容死循环问题，但仍存在**数据覆盖**、**size计数不准确**等问题。多线程必须使用ConcurrentHashMap。
# 26. 红黑树树化与退化时机

HashMap中链表何时转为红黑树？红黑树何时退化为链表？
**原理分析**
**树化条件（两个同时满足）：**
1. 链表长度 >= **TREEIFY_THRESHOLD（8）**
2. 数组长度 >= **MIN_TREEIFY_CAPACITY（64）**
```java
if (binCount >= TREEIFY_THRESHOLD - 1)  // 链表长度>=8
    treeifyBin(tab, hash);
// treeifyBin中判断数组长度
if (tab == null || (n = tab.length) < MIN_TREEIFY_CAPACITY)
    resize();  // 容量不足时扩容而不是树化
```
**退化条件：**
1. 链表长度 <= **UNTREEIFY_THRESHOLD（6）**
2. 扩容时拆分红黑树，如果低高位链表长度 <= 6，退化
**为什么选8和6：**
- **泊松分布**：随机hashCode下，链表长度达到8的概率极低（0.00000006），几乎不可能
- **空间权衡**：TreeNode占用空间是普通Node的2倍，所以只在必要时树化
- **7作为缓冲**：避免在8附近频繁树化/退化
```java
// 链表 vs 红黑树 平均查找长度
// 链表: n/2 = 8/2 = 4
// 红黑树: log(8) = 3
// 长度8时树化有性能提升，长度6时链表更快
```
> 为什么树化需要数组长度>=64？
如果数组长度<64，大量节点集中在少数桶中，说明hash分布不均匀，此时扩容比树化更有效，可以重新散列让数据分散。
# 27. Comparable与Comparator的区别

Comparable和Comparator有什么区别？各自如何选择？
**原理分析**
**Comparable（自然排序）：**
```java
public interface Comparable<T> {
    public int compareTo(T o);
}
// 返回值: 正数→当前对象大，负数→当前对象小，0→相等
```
- 在类内部实现，定义**默认排序规则**
- `String`、`Integer`等基础类都实现了Comparable
**Comparator（比较器排序）：**
```java
public interface Comparator<T> {
    int compare(T o1, T o2);
}
```
- 在类外部实现，定义**临时排序规则**
- 可用于排序规则不同的场景，不修改原类
**使用示例：**
```java
// Comparable：按年龄升序
class Person implements Comparable<Person> {
    int age;
    public int compareTo(Person o) {
        return this.age - o.age;
    }
}
// Comparator：按年龄降序
Comparator<Person> desc = (p1, p2) -> p2.age - p1.age;
```
**区别总结：**
| 特性 | Comparable | Comparator |
|-----|-----------|-----------|
| 位置 | 类内部 | 类外部 |
| 方法 | compareTo() | compare() |
| 参数 | this vs o | o1 vs o2 |
| 修改原类 | 需要 | 不需要 |
| 排序规则 | 单一 | 可多个 |
> TreeMap中使用哪个？
两者都可以。创建TreeMap时如果没有传Comparator，则使用key的Comparable自然排序。
```java
// 使用自然排序
TreeMap<Person, String> map1 = new TreeMap<>();
// 使用比较器
TreeMap<Person, String> map2 = new TreeMap<>((a,b) -> a.age - b.age);
```
# 28. WeakHashMap的原理与使用场景

WeakHashMap的原理是什么？它和HashMap有什么区别？
**原理分析**
**WeakHashMap：**
- 基于**弱引用（WeakReference）** 实现的HashMap
- 当key除了WeakHashMap中的引用外没有其他强引用时，**GC时会自动回收**该key对应的entry
- 常用于**缓存场景**，防止内存泄漏
**实现原理：**
```java
public class WeakHashMap<K,V> extends AbstractMap<K,V> implements Map<K,V> {
    // Entry继承WeakReference，key被弱引用包装
    private static class Entry<K,V> extends WeakReference<Object> {
        V value;
        final int hash;
        Entry<K,V> next;
    }
    // ReferenceQueue：记录被GC回收的key
    private final ReferenceQueue<Object> queue = new ReferenceQueue<>();
}
```
**自动回收机制：**
1. key被GC回收（不再有强引用）
2. 被回收的key进入ReferenceQueue
3. 下次操作WeakHashMap时，expungeStaleEntries()清理对应的entry
**与HashMap的区别：**
| 特性 | WeakHashMap | HashMap |
|-----|------------|---------|
| key引用类型 | 弱引用 | 强引用 |
| GC回收 | key无强引用时自动回收entry | 不会自动回收 |
| 使用场景 | 缓存、ThreadLocal | 常规存储 |
> ThreadLocal中为什么使用弱引用？
```java
static class ThreadLocalMap {
    static class Entry extends WeakReference<ThreadLocal<?>> {
        Object value;
    }
}
```
ThreadLocalMap的key（ThreadLocal实例）若为强引用，即使外部不再使用ThreadLocal，也无法被GC回收，导致内存泄漏。使用弱引用后，ThreadLocal无外部引用时即可被GC回收，但value仍需要手动remove()避免泄漏。
# 29. PriorityQueue优先级队列的原理

PriorityQueue的实现原理是什么？它是如何保证优先级的？
**原理分析**
**数据结构：**
- 基于**二叉堆（Binary Heap）** 实现，底层是Object数组
- **小顶堆**（默认）：堆顶是最小元素，按自然顺序或Comparator排序
- **大顶堆**：通过自定义Comparator实现
```java
public class PriorityQueue<E> extends AbstractQueue<E> {
    transient Object[] queue;  // 底层数组
    private final Comparator<? super E> comparator;
    // 默认容量11
    private static final int DEFAULT_INITIAL_CAPACITY = 11;
}
```
**核心操作：**
1. **入队（offer）**：元素插入数组末尾，然后**上浮（siftUp）** 与父节点比较，小则交换
2. **出队（poll）**：取出堆顶元素，将末尾元素移到堆顶，然后**下沉（siftDown）** 与子节点比较，大则交换
```java
// 入队：上浮
private void siftUpComparable(int k, E x) {
    Comparable<? super E> key = (Comparable<? super E>) x;
    while (k > 0) {
        int parent = (k - 1) >>> 1;  // 父节点位置
        if (key.compareTo((E) queue[parent]) >= 0) break;
        queue[k] = queue[parent];
        k = parent;
    }
    queue[k] = key;
}
```
**特性：**
- **非线程安全**，线程安全版：PriorityBlockingQueue
- **不允许null**
- 迭代器**不保证顺序**，遍历是无序的
- 默认容量11，扩容策略：容量<64时翻倍+2，>=64时扩容50%
> PriorityQueue如何实现大顶堆？
传入自定义Comparator，反转比较逻辑：
```java
// 大顶堆
PriorityQueue<Integer> maxHeap = new PriorityQueue<>((a, b) -> b - a);
```
# 30. Deque双端队列与ArrayDeque

Deque和ArrayDeque是什么？它们和LinkedList有什么区别？
**原理分析**
**Deque接口：**
- 双端队列（Double Ended Queue），支持**两端**插入和移除
- 既可当作**队列**使用（FIFO），也可当作**栈**使用（LIFO）
```java
public interface Deque<E> extends Queue<E> {
    // 双端操作
    void addFirst(E e);    // 头部插入
    void addLast(E e);     // 尾部插入
    E removeFirst();       // 移除头部
    E removeLast();        // 移除尾部
    E getFirst();          // 获取头部
    E getLast();           // 获取尾部
    // 栈操作
    void push(E e);        // 入栈
    E pop();               // 出栈
}
```
**ArrayDeque实现：**
```java
public class ArrayDeque<E> extends AbstractCollection<E> implements Deque<E> {
    transient Object[] elements;  // 底层循环数组
    transient int head;           // 头指针
    transient int tail;           // 尾指针
}
```
- 底层是**循环数组**，比LinkedList更省内存（无需维护节点指针）
- 默认容量16，扩容为**2倍**
- **不支持null**
**LinkedList也实现了Deque**，但底层是双向链表，节点有额外指针开销。
**ArrayDeque vs LinkedList：**
| 特性 | ArrayDeque | LinkedList |
|-----|-----------|------------|
| 底层 | 循环数组 | 双向链表 |
| 内存 | 紧凑，无额外指针 | 每个节点有前后指针 |
| 随机访问 | 不支持 | 不支持 |
| 两端操作 | **O(1)** | O(1) |
| 中间插入 | O(n) | O(n) |
| null支持 | 不允许 | 允许 |
> 为什么推荐ArrayDeque作为栈/队列？
- 作为栈：比Stack快（Stack继承Vector，有synchronized开销）
- 作为队列：比LinkedList快（数组连续内存，局部性好）
```java
// 栈：推荐ArrayDeque
Deque<String> stack = new ArrayDeque<>();
stack.push("a");
stack.pop();
// 队列：推荐ArrayDeque
Queue<String> queue = new ArrayDeque<>();
queue.offer("a");
queue.poll();
```
# 31. Queue接口的方法体系

Queue接口定义了哪些方法？它们有什么区别？
**原理分析**
**Queue接口方法：**
| 操作 | 抛出异常 | 返回特殊值 |
|-----|---------|-----------|
| 插入 | add(e) | **offer(e)** |
| 移除 | remove() | **poll()** |
| 检查 | element() | **peek()** |
- **抛出异常**：队列满时add抛出IllegalStateException，队列空时remove/element抛出NoSuchElementException
- **返回特殊值**：offer返回false，poll/peek返回null
**Deque扩展方法：**
```java
// 头部操作
void addFirst(E e);     boolean offerFirst(E e);
E removeFirst();         E pollFirst();
E getFirst();            E peekFirst();
// 尾部操作
void addLast(E e);       boolean offerLast(E e);
E removeLast();          E pollLast();
E getLast();             E peekLast();
```
**常用实现类：**
| 类 | 特点 |
|---|------|
| LinkedList | 双向链表，可作队列/栈/双端队列 |
| ArrayDeque | 循环数组，高效，**最推荐的队列实现** |
| PriorityQueue | 二叉堆，按优先级出队 |
| ConcurrentLinkedQueue | 无锁并发队列，CAS实现 |
| BlockingQueue | 阻塞队列接口 |
> 为什么要设计两套方法？
生产环境中推荐使用offer/poll/peek，避免异常处理开销：
```java
// 推荐
if (queue.offer(item)) { /* 成功 */ }
// 不推荐
try { queue.add(item); } catch (IllegalStateException e) { /* 处理 */ }
```
# 32. BlockingQueue阻塞队列

BlockingQueue是什么？它有哪些实现类？
**原理分析**
**BlockingQueue：**
- 支持**阻塞操作**的并发队列
- 当队列空时，take()会阻塞直到有元素
- 当队列满时，put()会阻塞直到有空位
```java
public interface BlockingQueue<E> extends Queue<E> {
    void put(E e) throws InterruptedException;     // 满时阻塞
    E take() throws InterruptedException;          // 空时阻塞
    boolean offer(E e, long timeout, TimeUnit unit); // 限时插入
    E poll(long timeout, TimeUnit unit);            // 限时获取
}
```
**常用实现类：**
| 实现类 | 特点 | 底层 |
|-------|------|------|
| **ArrayBlockingQueue** | 有界，**公平性可设置** | 数组+ReentrantLock |
| **LinkedBlockingQueue** | 可选有界（默认Integer.MAX_VALUE），吞吐量高 | 链表+两把锁（take/put分离） |
| **PriorityBlockingQueue** | 无界，按优先级出队 | 二叉堆+ReentrantLock |
| **SynchronousQueue** | 无容量，每个put必须等待一个take | 一对一传递 |
| **DelayQueue** | 延迟出队，元素需实现Delayed | PriorityQueue+ReentrantLock+Condition |
| **LinkedTransferQueue** | 无锁，提供transfer()方法 | CAS |
**ArrayBlockingQueue与LinkedBlockingQueue对比：**
| 特性 | ArrayBlockingQueue | LinkedBlockingQueue |
|-----|-------------------|-------------------|
| 有界性 | **必须指定容量** | 可选（默认无界） |
| 锁 | 1把ReentrantLock | 2把（put/take分离） |
| 数据结构 | 循环数组 | 单向链表 |
| 吞吐量 | 中等 | **更高** |
> BlockingQueue在哪些场景使用？
最经典的是**生产者-消费者模式**：
```java
BlockingQueue<Object> queue = new ArrayBlockingQueue<>(100);
// 生产者
new Thread(() -> {
    while (true) queue.put(produce());
}).start();
// 消费者
new Thread(() -> {
    while (true) consume(queue.take());
}).start();
```
# 33. SynchronousQueue同步队列

SynchronousQueue的原理是什么？它和普通BlockingQueue有什么区别？
**原理分析**
**SynchronousQueue：**
- **容量为0**的阻塞队列，内部不存储任何元素
- 每个put操作必须**等待**一个take操作，否则阻塞
- 每个take操作必须**等待**一个put操作，否则阻塞
- 可以看作线程之间的**一对一交接**机制
```java
SynchronousQueue<String> queue = new SynchronousQueue<>();
// 线程A
new Thread(() -> {
    try { queue.put("data"); }  // 阻塞直到被take
    catch (InterruptedException e) { }
}).start();
// 线程B
new Thread(() -> {
    try { String data = queue.take(); }  // 阻塞直到有put
    catch (InterruptedException e) { }
}).start();
```
**两种模式：**
1. **公平模式（TransferQueue）**：FIFO，等待线程排队，保证先进先出
2. **非公平模式（TransferStack）**：LIFO，无等待队列，吞吐量更高
```java
// 公平模式
SynchronousQueue<String> fair = new SynchronousQueue<>(true);
// 非公平模式（默认）
SynchronousQueue<String> unfair = new SynchronousQueue<>(false);
```
**与普通BlockingQueue的区别：**
| 特性 | SynchronousQueue | LinkedBlockingQueue |
|-----|-----------------|-------------------|
| 容量 | **0** | 可设置 |
| 存储 | 不存储元素 | 存储元素 |
| 使用场景 | 直接交接、线程池 | 生产者-消费者缓冲 |
**在线程池中的应用：**
`Executors.newCachedThreadPool()`内部使用SynchronousQueue，任务提交后直接交给空闲线程，没有空闲线程则创建新线程：
```java
public static ExecutorService newCachedThreadPool() {
    return new ThreadPoolExecutor(0, Integer.MAX_VALUE,
                                  60L, TimeUnit.SECONDS,
                                  new SynchronousQueue<Runnable>());
}
```
> SynchronousQueue的peek()返回什么？
始终返回null，因为队列中不存储任何元素。
