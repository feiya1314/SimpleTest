# 1. 反射的原理是什么？主要API有哪些？

**原理：** JVM在类加载时将.class文件解析为 `java.lang.Class` 对象，反射通过这个Class对象获取类的元数据（方法、字段、构造器等）。

**获取Class对象的三种方式：**

```java
Class<?> clazz = Class.forName("com.example.User");
Class<?> clazz = User.class;
Class<?> clazz = user.getClass();
```

**主要API：**

```java
// 获取构造器并实例化
Constructor<?> constructor = clazz.getDeclaredConstructor(String.class);
User user = (User) constructor.newInstance("张三");

// 获取方法并调用
Method method = clazz.getDeclaredMethod("getName");
String name = (String) method.invoke(user);

// 获取字段并修改
Field field = clazz.getDeclaredField("name");
field.setAccessible(true);    // 访问private字段
field.set(user, "新名字");

// 获取注解
Annotation[] annotations = clazz.getAnnotations();
```

**setAccessible：** 抑制Java语言访问权限检查，使反射可以访问private成员。频繁调用有性能开销，应缓存反射对象。

# 2. 反射的性能开销如何？如何优化？

**性能开销：**
- 反射比直接调用慢（跳过JVM内联优化、类型检查、安全检查等）
- 慢约 **1~2个数量级**
- 优化方式：缓存Method/Field对象、尽量用接口调用、使用setAccessible(true)减少安全检查

# 3. Spring框架中反射的应用有哪些？

- IOC容器：通过反射读取类的构造器、字段信息，实现**依赖注入**
- @Autowired：通过反射字段上的注解，**注入依赖对象**
- AOP：结合动态代理，对目标类创建代理对象
- 配置解析：读取@Component、@Service等注解，扫描包**注册Bean**
- SpEL表达式：反射调用方法访问对象属性

# 4. JDK动态代理的原理是什么？怎么实现？

基于**接口**，通过 `java.lang.reflect.Proxy` 和 `InvocationHandler` 在运行时动态生成代理类。

```java
// InvocationHandler - 调用处理器
public class LogHandler implements InvocationHandler {
    private final Object target;

    public LogHandler(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("before");
        Object result = method.invoke(target, args);
        System.out.println("after");
        return result;
    }
}

// 创建代理对象
UserService proxy = (UserService) Proxy.newProxyInstance(
    target.getClass().getClassLoader(),
    target.getClass().getInterfaces(),
    new LogHandler(target)
);
proxy.doSomething();
```

# 5. CGLIB动态代理的原理是什么？怎么实现？

基于**继承**，通过ASM字节码技术生成目标类的子类，覆盖非final方法。

```java
// MethodInterceptor
public class LogInterceptor implements MethodInterceptor {
    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        System.out.println("before");
        Object result = proxy.invokeSuper(obj, args);
        System.out.println("after");
        return result;
    }
}

// 创建代理
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(UserService.class);
enhancer.setCallback(new LogInterceptor());
UserService proxy = (UserService) enhancer.create();
```

# 6. JDK动态代理 vs CGLIB的区别？

| 维度 | JDK动态代理 | CGLIB |
|------|------------|-------|
| 原理 | 基于接口，生成实现类 | 基于继承，生成子类 |
| 要求 | 目标类必须实现接口 | 目标类不能是final |
| 目标方法 | 接口中声明的方法 | 非final方法（final/static不行） |
| 依赖 | JDK原生，无需额外包 | 需要引入cglib/ASM |
| 性能 | 创建快，调用稍慢 | 创建慢，调用快（MethodProxy优化） |

# 7. Spring AOP如何选择代理方式？

- 目标类实现了接口 → 默认用**JDK动态代理**
- 目标类未实现接口 → 用**CGLIB**
- Spring Boot 2.x+ 默认用CGLIB（proxy-target-class=true）

# 8. 动态代理的使用场景有哪些？

- **AOP**面向切面编程（事务、日志、权限控制）
- **RPC框架**远程调用（对本地接口生成远程调用代理）
- **延迟加载**（MyBatis懒加载代理）
- **方法拦截器**

# 9. 注解的本质和保留策略？

**元注解：**

| 元注解 | 说明 |
|--------|------|
| @Retention | 保留策略 |
| @Target | 可修饰的目标（方法、字段、类等） |
| @Inherited | 是否可继承，父类注解可被子类继承 |
| @Documented | 是否包含在Javadoc中 |
| @Repeatable | 是否可重复标注 |

**RetentionPolicy（保留策略）：**

| 策略 | 级别 | 说明 |
|------|------|------|
| SOURCE | 源码 | 编译后丢弃，如 @Override |
| CLASS | 字节码 | 编译到class，运行时不可见（默认） |
| RUNTIME | 运行时 | 可通过反射读取，如 @Autowired |

# 10. 自定义注解如何实现？

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Log {
    String value() default "";
    Level level() default Level.INFO;
}
```

# 11. 运行时注解 vs 编译时注解？APT是什么？

| 类型 | 保留策略 | 获取方式 | 典型应用 |
|------|---------|---------|---------|
| 运行时注解 | RUNTIME | 反射读取 | Spring @Autowired |
| 编译时注解 | SOURCE/CLASS | APT处理 | Lombok @Data |

**APT（Annotation Processing Tool）：** 编译时注解处理器，在编译期扫描和处理注解，自动生成代码。
- `@Override`：SOURCE级别，编译期语法检查
- **Lombok**：编译时通过APT生成getter/setter/构造器等，class文件中已有完整代码
- **AbstractProcessor**：自定义APT处理器，继承该类实现process()方法，生成Java源文件或代码
