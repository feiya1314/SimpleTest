# 1. 反射的原理是什么？主要API有哪些？

**原理：** JVM在类加载时将.class文件解析为 `java.lang.Class` 对象，反射通过这个Class对象获取类的元数据（方法、字段、构造器等）。

**获取Class对象的三种方式：**

```java
Class<?> clazz = Class.forName("com.example.User");
Class<?> clazz = User.class;
Class<?> clazz = user.getClass();
```

**主要API：**

```java
// 获取构造器并实例化
Constructor<?> constructor = clazz.getDeclaredConstructor(String.class);
User user = (User) constructor.newInstance("张三");

// 获取方法并调用
Method method = clazz.getDeclaredMethod("getName");
String name = (String) method.invoke(user);

// 获取字段并修改
Field field = clazz.getDeclaredField("name");
field.setAccessible(true);    // 访问private字段
field.set(user, "新名字");

// 获取注解
Annotation[] annotations = clazz.getAnnotations();

// 判断类型间关系
boolean isSub = clazz.isAssignableFrom(OtherClass.class); // clazz是否兼容OtherClass
```

**setAccessible：** 抑制Java语言访问权限检查，使反射可以访问private成员。频繁调用有性能开销，应缓存反射对象。

**isAssignableFrom：** 判断当前Class对象所表示的类或接口是否与指定Class所表示的类或接口相同，或是其超类/超接口（与 instanceof 不同，isAssignableFrom 是类维度的判断，不依赖实例）。

# 2. 反射的性能开销如何？如何优化？

**性能开销：**

- 反射比直接调用慢（跳过JVM内联优化、类型检查、安全检查等）
- 慢约 **1\~2个数量级**
- 优化方式：缓存Method/Field对象、尽量用接口调用、使用setAccessible(true)减少安全检查

# 3. Spring框架中反射的应用有哪些？

- **IOC容器**：通过反射读取类的构造器、字段信息，实现依赖注入
- **@Autowired**：通过反射字段上的注解，注入依赖对象
- **AOP**：结合动态代理，对目标类创建代理对象
- **配置解析**：读取@Component、@Service等注解，扫描包注册Bean
- **SpEL表达式**：反射调用方法访问对象属性

# 4. JDK动态代理的原理是什么？怎么实现？

基于**接口**，通过 `java.lang.reflect.Proxy` 和 `InvocationHandler` 在运行时动态生成代理类。

**Proxy.newProxyInstance 执行过程：**

**1** 根据传入的接口数组，动态在内存中生成与 .class 文件等同的字节码
**2** 将字节码转换成对应的 Class 对象
**3** 调用 newInstance() 创建代理实例，传入 InvocationHandler

```java
// InvocationHandler - 调用处理器
public class LogHandler implements InvocationHandler {
    private final Object target;

    public LogHandler(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("before");
        Object result = method.invoke(target, args);
        System.out.println("after");
        return result;
    }
}

// 创建代理对象
UserService proxy = (UserService) Proxy.newProxyInstance(
    target.getClass().getClassLoader(),
    target.getClass().getInterfaces(),
    new LogHandler(target)
);
proxy.doSomething();
```

# 5. CGLIB动态代理的原理是什么？怎么实现？

基于**继承**，通过ASM字节码技术生成目标类的子类，覆盖非final方法。

```java
// MethodInterceptor
public class LogInterceptor implements MethodInterceptor {
    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        System.out.println("before");
        Object result = proxy.invokeSuper(obj, args);
        System.out.println("after");
        return result;
    }
}

// 创建代理
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(UserService.class);
enhancer.setCallback(new LogInterceptor());
UserService proxy = (UserService) enhancer.create();
```

# 6. JDK动态代理 vs CGLIB的区别？

| 维度 | JDK动态代理 | CGLIB |
| --- | --- | --- |
| 原理 | 基于接口，生成实现类 | 基于继承，生成子类 |
| 要求 | 目标类必须实现接口 | 目标类不能是final |
| 目标方法 | 接口中声明的方法 | 非final方法（final/static不行） |
| 依赖 | JDK原生，无需额外包 | 需要引入cglib/ASM |
| 性能 | 创建快，调用稍慢 | 创建慢，调用快（MethodProxy优化） |

# 7. Spring AOP如何选择代理方式？

- 目标类实现了接口 → 默认用**JDK动态代理**
- 目标类未实现接口 → 用**CGLIB**
- Spring Boot 2.x+ 默认用CGLIB（proxy-target-class=true）

# 8. 动态代理的使用场景有哪些？

- **AOP**面向切面编程（事务、日志、权限控制）
- **RPC框架**远程调用（对本地接口生成远程调用代理）
- **延迟加载**（MyBatis懒加载代理）
- **方法拦截器**

# 9. 注解的本质和保留策略？

**元注解：**

| 元注解 | 说明 |
| --- | --- |
| @Retention | 保留策略 |
| @Target | 可修饰的目标（方法、字段、类等） |
| @Inherited | 是否可继承，父类注解可被子类继承 |
| @Documented | 是否包含在Javadoc中 |
| @Repeatable | 是否可重复标注 |

**RetentionPolicy（保留策略）：**

| 策略 | 级别 | 说明 |
| --- | --- | --- |
| SOURCE | 源码 | 编译后丢弃，如 @Override |
| CLASS | 字节码 | 编译到class，运行时不可见（默认） |
| RUNTIME | 运行时 | 可通过反射读取，如 @Autowired |

# 10. 自定义注解如何实现？

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Log {
    String value() default "";
    Level level() default Level.INFO;
}

使用时可以：
// 获取注解，根据注解中的内容进行对应的业务逻辑处理
Annotation[] annotations = clazz.getAnnotations();

比如有注解中的操作类型，记录不同的操作日志等
```

# 11. 运行时注解 vs 编译时注解？APT是什么？

| 类型 | 保留策略 | 获取方式 | 典型应用 |
| --- | --- | --- | --- |
| 运行时注解 | RUNTIME | 反射读取 | Spring @Autowired |
| 编译时注解 | SOURCE/CLASS | APT处理 | Lombok @Data |

**APT（Annotation Processing Tool）：** 编译时注解处理器，在编译期扫描和处理注解，自动生成代码。

- @Override：SOURCE级别，编译期语法检查
- **Lombok**：编译时通过APT生成getter/setter/构造器等，class文件中已有完整代码
- **AbstractProcessor**：自定义APT处理器，继承该类实现process()方法，生成Java源文件或代码

# 12. Unsafe是什么？如何获取？

Unsafe是 `sun.misc` 包下的单例类，提供直接操作堆外内存、CAS、线程调度、对象实例化等底层能力，类似C语言指针。因其不安全，官方不推荐直接使用。

**获取方式：**

**1** 通过 `-Xbootclasspath/a` 将类路径追加到引导类加载器，调用 `Unsafe.getUnsafe()`

**2** 通过反射获取 `theUnsafe` 字段：

```java
Field field = Unsafe.class.getDeclaredField("theUnsafe");
field.setAccessible(true);
Unsafe unsafe = (Unsafe) field.get(null);
```

# 13. Unsafe的核心功能有哪些？

| 功能分类 | 主要方法 | 说明 |
| --- | --- | --- |
| 内存操作 | allocateMemory / freeMemory / setMemory / copyMemory | 分配、释放堆外内存，绕过JVM堆管理 |
| CAS操作 | compareAndSwapInt / compareAndSwapLong / compareAndSwapObject | 原子比较并交换，CPU指令 cmpxchg |
| 对象操作 | allocateInstance / objectFieldOffset / putObject / getObject | 绕过构造器创建对象，直接读写字段 |
| 线程调度 | park / unpark | 挂起/恢复线程，LockSupport 基于此实现 |
| Class相关 | defineClass / defineAnonymousClass / staticFieldOffset | 动态定义类、获取静态字段偏移 |
| 内存屏障 | loadFence / storeFence / fullFence | 禁止指令重排序 |
| 数组相关 | arrayBaseOffset / arrayIndexScale | 获取数组首元素偏移和元素大小 |
| 系统信息 | addressSize / pageSize | 获取指针大小和内存页大小 |

# 14. Unsafe如何实现CAS？应用场景？

**原理：** CAS（Compare-And-Swap）是CPU原子指令（cmpxchg），通过比较内存当前值与预期值，相等则更新为新值，否则重试。

```java
// 获取字段偏移量
long valueOffset = unsafe.objectFieldOffset(AtomicInteger.class.getDeclaredField("value"));
// 执行CAS
unsafe.compareAndSwapInt(this, valueOffset, expect, update);
```

**应用场景：**

- **AtomicInteger / AtomicLong** 等原子类
- **AQS** 同步器框架（ReentrantLock、Semaphore等）
- **ConcurrentHashMap** 并发扩容和计数
- 本质：无锁并发，避免synchronized阻塞

# 15. allocateInstance有什么作用？

绕过构造器、初始化代码和JVM安全检查直接创建对象，即使构造器是private也能实例化。

```java
User user = (User) unsafe.allocateInstance(User.class); // 不调用构造器
```

**应用场景：**

- **Gson反序列化**：无默认构造器时通过 allocateInstance 创建对象
- **Objenesis**：绕过构造器的对象生成工具
- **深拷贝**：跳过构造器逻辑

# 16. 堆外内存如何分配和回收？

**分配：** 通过 `unsafe.allocateMemory(bytes)` 在JVM堆外分配内存，返回内存地址。

**典型实现 DirectByteBuffer：**

```java
// 分配堆外内存
long address = unsafe.allocateMemory(capacity);
unsafe.setMemory(address, capacity, (byte) 0);

// 释放
unsafe.freeMemory(address);
```

**回收机制：** DirectByteBuffer 关联 **Cleaner**（虚引用），当DirectByteBuffer被GC回收时，Cleaner自动调用 `freeMemory()` 释放堆外内存。

- 堆外内存优点：减少GC停顿、提升IO性能（避免堆内到堆外的数据拷贝）
- 应用：**Netty**、**MINA** 等NIO框架的缓冲池

# 17. Unsafe的内存屏障方法有哪些？

| 方法 | 作用 |
| --- | --- |
| loadFence() | 禁止load重排序，保证屏障前的读操作完成后才执行后续读 |
| storeFence() | 禁止store重排序，保证屏障前的写操作完成后才执行后续写 |
| fullFence() | 禁止load/store重排序 |

**应用场景：** `StampedLock` 的乐观读锁通过 `loadFence` 保证数据一致性，避免读取到过期数据。
