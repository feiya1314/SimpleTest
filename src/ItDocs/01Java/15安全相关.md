# 1. 什么是Java SecurityManager？

**SecurityManager**是Java提供的一个安全管理器，允许应用程序在运行前评估操作的安全性，决定是否允许执行该操作。它通过**沙箱机制**限制不可信代码的权限，防止恶意代码访问系统资源（文件、网络、线程等）。

# 2. SecurityManager的核心检查机制是怎样的？

通过**checkXxx()**方法体系实现权限控制：

- 每当代码执行敏感操作时，JVM会调用对应的check方法
- check方法内部调用**AccessController.checkPermission()**检查权限
- 若不满足安全策略，抛出**SecurityException**，阻止操作执行
- 若继承SecurityManager并**重写checkXxx()**方法，可覆盖默认检查逻辑

# 3. 如何启用SecurityManager？

三种方式启用：

- **命令行启动**：`java -Djava.security.manager -Djava.security.policy=my.policy App`
- **代码中动态设置**：`System.setSecurityManager(new SecurityManager())`
- **默认策略文件**：不指定策略文件时，使用JRE `lib/security/java.policy` 和 `~/.java.policy`

# 4. 安全策略文件（.policy）的格式是什么？

策略文件使用**Grant/CodeBase/Permission**结构：

```
grant codeBase "file:/path/to/jar" {
    permission java.io.FilePermission "/tmp/*", "read,write";
    permission java.net.SocketPermission "localhost:8080", "connect";
};
```

- **codeBase**：指定代码来源（可选，不指定则对所有代码生效）
- **permission**：由**权限类型**、**目标名称**、**操作列表**三部分组成
- 常见权限类型：`FilePermission`、`SocketPermission`、`RuntimePermission`、`ReflectPermission`、`PropertyPermission`

# 5. 常用的checkXxx方法有哪些？

| 方法 | 保护的资源 |
|------|-----------|
| **checkRead(String file)** | 文件读操作 |
| **checkWrite(String file)** | 文件写操作 |
| **checkConnect(String host, int port)** | 网络连接 |
| **checkListen(int port)** | 端口监听 |
| **checkDelete(String file)** | 文件删除 |
| **checkExec(String cmd)** | 执行外部命令 |
| **checkExit(int status)** | JVM退出 |
| **checkPropertyAccess(String key)** | 系统属性访问 |
| **checkPermission(Permission perm)** | 通用权限检查（所有check方法的最终入口） |

# 6. SecurityManager在Java新版本中的变化？

- **Java 17**：标记为**弃用（deprecated）**，建议移除
- **Java 18**：**默认禁用**，但仍可通过系统属性启用
- **更高版本**：计划移除，但仍保留兼容性选项
- **替代方案**：推荐使用**Java Platform Module System（JPMS）**的模块化访问控制，以及**操作系统级安全机制**（容器、seccomp等）
- 迁移建议：检查代码中对`System.getSecurityManager()`和自定义SecurityManager的依赖，改用模块化权限控制

# 7. 实际开发中什么场景会用到SecurityManager？

- **Web容器**（Tomcat等）隔离不同Web应用的权限
- **Applet**（已废弃）和**Java Web Start**限制不可信代码
- **插件系统**运行第三方插件时限制其访问范围
- **代码托管/沙箱环境**（如在线判题系统）防止恶意代码破坏宿主机
- 注：在现代开发中，**容器化（Docker）+系统权限控制**逐渐替代了SecurityManager的角色
